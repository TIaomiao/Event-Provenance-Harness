1. 研究问题

研究自然语言取数要求能否被正确解释并执行——在纵向 EHR 记录上选出任务真正需要的记录集合、时间点与来源，并如实交出未决状态

本节是给读者（含师兄）的短说明；执行规则与详细状态见 AGENTS 与 CONTROL_PANEL。

两条记录的说明性例子（合成，非实测失败）：同一位患者有两条同一项目的记录，一次落在相对日 0、一次落在相对日 5。问「相对日 0 当天或之前、时间上最靠后的一条」，答案是相对日 0 那条；问「相对日 0 之后最早的一条」，答案换成相对日 5 那条；问「相对日 0 到 5 之间全部」，两条都要给。记录表一个字没变，问法一变，正确答案就变。 此例为合成说明，不代表任何实测结果。

2. 实际比较与结果

逐行原文：只给相关页面的逐行文字，没有按化验记录成组。记录表：同样页面，已整理成一条条记录（含值、单位、两个时间）。 直接选择：模型自己挑记录。先给条件再执行：模型只翻译出条件（时间角色、时间窗、取最近/最早/全部），由同一个固定程序取数。

本次运行：10 个开发患者包、60 个任务 × 两种形态 × 两种解法 = 240 条（2026-10-10）。题面只用院内词汇暗示时间角色，从不点名字段。

解法输入：逐行原文输入：记录表
直接选择58/6054/60
先给条件再执行60/6060/60

同一病人、同一题，只换形态或解法。状态正确只在「直接选择」口径下报。

四句话读完：① 整理成表没有让选择更准——配对比较里逐行原文反而多对 4 题。② 整理成表让输入 token 降到约 1/48、费用降到约 1/13，这是唯一有证据的整理收益。③ 先给条件再执行把残余失误全消掉（两种形态都满分，配对里多对 8 题、从未更差）；它的记录集合由固定程序执行得出。④ 失误集中在「枚举一个集合」：8 处里 7 处在窗口题。

研究结论：把逐行原文整理成记录表之后，选择正确性没有提升（配对里未整理那端反而多对 4 题）；整理的价值在成本上——同为直接选择，记录表的输入 token 约 1/48、费用约 1/11。让模型先说出条件、再由固定程序执行，两种形态都 60/60，消掉了直接选择的全部残余失误。 条件改为必须从自然语言推断后，两端正确率仍接近上限（54–60/60），题目对当前模型依然偏浅：本轮拿到的是「整理更省」的证据，不是「整理更准」的证据。

上一轮（2026-10-06，条件由宿主显式声明）要分开读：直接选择 120/120； 先计划再执行 当时 110/120、修正后离线重放 120/120（重放不是新的模型运行）。

3. 关键边界

  • 记录来自整理后的记录表（规则/OCR 抽取并经校验），不是人工核对的原文事实；10 个包全是开发集，患者级统计功效很弱。
  • 本轮 60 个参考全为「有答案」，未覆盖「该说未决时说未决」；方法与供应商无关性均未被证明。
  • 逐行原文远长于记录表，形态差异混了结构与长度；本轮无准确率差异，削弱但不消除该担心。
  • 时间角色（采集 vs 报告）不可观测：60 题里 0 题在两种角色下答案不同，故不对角色推断下结论。
  • 来源事实人工核对尚未完成。

参考等级：规则/OCR 派生的选择参考（冻结记录表上按定义独立计算），人工原页核对尚未完成。

4. 下一步与师兄判断

当前检验问题：换成真正会拉开差距的任务类型之后，整理与不整理、直接选择与先给条件再执行，会不会出现正确性差异？

真实执行状态：条件推断这一轮已跑完（240 条）；残余失误集中在「枚举集合、判断空集」。仍未运行：更难的题型（两端仍接近上限，需要它才可能拉开差异）；空集与未决的参考用例（本轮参考全为有答案）——不填预期成绩。

需要师兄判断：

  1. 下一轮是否把重点放在集合枚举与空集判断（本轮 8 处失误里 7 处在此），而不是继续加时间点题型。
  2. 「整理更省」这条成本结论是否足以支撑 AI-Ready 的主表，还是必须先拿到正确性上的差异。
