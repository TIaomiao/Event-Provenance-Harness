1. 研究问题

研究自然语言取数要求能否被正确解释并执行——在纵向 EHR 记录上选出任务真正需要的记录集合、时间点与来源，并如实交出未决状态

本节是给读者（含师兄）的短说明；执行规则与详细状态见 AGENTS 与 CONTROL_PANEL。

两条记录的说明性例子（合成，非实测失败）：同一位患者有两条同一项目的记录，一次落在相对日 0、一次落在相对日 5。问「相对日 0 当天或之前、时间上最靠后的一条」，答案是相对日 0 那条；问「相对日 0 之后最早的一条」，答案换成相对日 5 那条；问「相对日 0 到 5 之间全部」，两条都要给。记录表一个字没变，问法一变，正确答案就变。 此例为合成说明，不代表任何实测结果。

2. 实际比较与结果

逐行原文：只给相关页面的逐行文字，没有按化验记录成组。记录表：同样页面，已整理成一条条记录（含值、单位、两个时间）。 直接选择：模型自己挑记录。先给条件再执行：模型只翻译出条件（时间角色、时间窗、取最近/最早/全部），由同一个固定程序取数。

本次运行：10 个开发患者包、62 个任务 × 两种形态 × 两种解法 = 248 条（2026-10-11）。任务**全部换成集合枚举与空集判断**；题面只用院内词汇暗示时间角色，从不点名字段。

直接选择58/6254/62

同一病人、同一题，只换形态或解法。状态正确只在「直接选择」口径下报。

四句话读完：① 整理成表没有让选择更准——配对里逐行原文反而多对 5 题。② 整理成表让输入 token 降到约 1/48、费用约 1/14，这是唯一有证据的整理收益。③ 空集判断模型全对（30/30）；难的是大集合的完整枚举（最大枚举族 8/10 与 6/10）。④ 直接选择的失误在记录表形态下全是「该有记录却返回空集」；先给条件再执行把失误全消掉（两形态都 62/62）。

研究结论：把任务压到集合枚举与空集判断上：空集判断模型全对（30/30）；难的是大集合的完整枚举，最大枚举族只有 8/10 与 6/10。直接选择的失误在记录表形态下全是「该有记录却返回空集」。整理成表仍然没有让选择更准（配对里逐行原文多对 5 题，与上一轮的 5:1 一致）；先给条件再执行把失误全消掉，两形态都 62/62。 两轮独立结果一致：整理成表没有正确性收益，只有成本收益（输入约 1/48、费用约 1/14）。成本不足以支撑 AI-Ready 主表；要拿正确性差异，需要把枚举负荷或干扰量再提高。

上一轮（2026-10-06，条件由宿主显式声明）要分开读：直接选择 120/120； 先计划再执行 当时 110/120、修正后离线重放 120/120（重放不是新的模型运行）。

3. 关键边界

  • 记录来自整理后的记录表（规则/OCR 抽取并经校验），不是人工核对的原文事实；10 个包全是开发集，患者级统计功效很弱。
  • 30 题参考是空集、32 题有答案；并列导致的「未决」参考在 10 个包里没能构造出来，仍未覆盖。
  • 逐行原文远长于记录表，形态差异混了结构与长度；两轮方向一致，但该混杂仍在。
  • 直接选择在逐行原文形态下仍达 58/62，题目整体偏浅，只有最大枚举族真正拉开。
  • 方法与供应商无关性未被证明；来源事实人工核对尚未完成。

参考等级：规则/OCR 派生的选择参考（冻结记录表上按定义独立计算），人工原页核对尚未完成。

4. 下一步与师兄判断

当前检验问题：既然空集判断与时间点定位都不是弱点、大集合枚举才是——把枚举负荷与干扰量再提高之后，整理与不整理会不会出现正确性差异？

真实执行状态：两轮都跑完；直接选择在最大枚举族掉到 8/10 与 6/10，其余族接近满分。仍未运行：并列导致的未决参考：重复时刻不落在窗口最新位置，10 个包里没能构造出来；跨文档或更长原文的更大枚举负荷：尚未运行——不填预期成绩。

需要师兄判断：

  1. 是否继续加枚举负荷（跨文档、更长原文、更多记录）以逼出正确性差异，还是承认在这类记录层上整理只有成本收益、把主表改成成本维度。
  2. 并列（未决）参考在 10 个包里没能构造出来，是否值得专门去找能构造出并列的包。
