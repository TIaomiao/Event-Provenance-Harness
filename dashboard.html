工作题目：可复用的医疗数据准备 Harness + Agent

一句话：把扫描病历中的处理能力组织成可调用、可核验、可复用的系统，并验证它对后续 AI 使用任务的帮助。

英文工作题目（未定稿）：A Reusable Data-Preparation Harness for Real Hospital Records: Does It Make Off-the-Shelf Agents More Useful?

Motivation

  1. 真实扫描病历这一段没人量过。 现有「AI-ready」工作要么是人工等级量表与准备指南（JCM 2026 的 0–2 级量表，作者自陈是提案而非经验证工具），要么比的是「已经结构化之后怎么排版」（FHIRBench 用合成 FHIR bundle）。从扫描件到可用数据中间那一段，没有人量过每一步各值多少。
  2. 「准备之后谁在用、怎么测」也还没回答。 Infherno 能把自由文本变成 FHIR，但止步于合成质量；FHIR-AgentBench 把「取对记录」与「答对问题」分开计分，但金标准只到资源 ID 级。「输出了结构」与「下游更好用」之间的连线没有被建立。
  3. 规模上可能不是「更贵」，而是「能不能做」。 队列级问题才是临床真正要的；在单次输入的限制下，原文的可答规模存在硬上限。

研究问题

把准备能力组织成可调用的 Harness、由 Agent 编排调用，能否让后续 AI 在真实的整理与核验任务上更可靠——与「原文 + 合理访问」和「可复现的常规准备流水线」相比，好在哪里、好在多少、代价是什么？

三个子问题：① 哪些准备动作各自贡献多少，哪些没有贡献？② 这种贡献是否跨模型、跨题目、跨病例仍然成立（而不是某个模型的偏好）？③ 代价（token、调用、建库、人工核对）与收益的关系是什么形状？

待验证主张（全部待检验，不预设正结果）

编号主张怎样会被推翻
H1（分任务类型）把字段含义、状态码与计数规则写成机器说明书，能提高下游 AI 在计数与阈值类问题上的表现；对单文档查找与极值类问题没有增益换模型 / 换题目后差异消失，或差异只来自输入 token 数
H2（分任务类型）把时间排成纵向轴并按天聚合，能提高时间类问题的表现同上；当前幅度区间很宽，只能报区间
H3（问法，不是负结论）来源与状态字段对 ①答题正确性 ②证据核验效率 ③错误识别分别有什么作用？——这是待答问题；已有的单题集观察不足以写成「无价值」
H4（限定条件）在单次输入、指定模型与配置下，不做准备时聚合类问题在规模上不可行；该上限在允许分块 / 检索后尚未测允许分块、检索、逐步读取后该上限消失
H5准备的收益可能体现在成本与运行失败率上，而不只在答对率在预定正确性容差内，成本与失败率也都不改善

候选贡献（候选，不是已成立）

  1. 一个可复用的准备 Harness：把版面读成行、单位归一、来源与状态、时间关联、机器说明书组织成可调用、可核验的接口。复用的含义必须可检验——跨病例、跨未见任务复用同一套组件，减少逐题定制。
  2. 一套对照评测设计：在候选任务上比较「完整方案」与两条对照（原文 + 合理访问、可复现的常规准备流水线），同时报质量、成本与失败，给出质量—成本曲线。
  3. 一份可复现的答案依据与判定协议：三层答案键（机械 / 独立模型 / 人工核对）+ 独立于被测库的程序对照键；机械问题与需要临床解释的问题分开。

本节要一起读的限定：多层级处理是候选消融，不预设每层正收益，层数不是贡献；主题是「整体方案 + 可复用性」，不是「逐层涨分」。目标架构、代码存在、接口可调用与端到端验证是四件不同的事。

检索边界与待核缺口

下面三条是检索覆盖内的待核缺口，不是结论。

  1. 「AI-ready」这个词已被占了三层：通用数据治理框架（E1/E2/E3 的分级与维度）、临床人工量表（S5 的 0–2 级）、序列化 / 表示实验（S2/S1）。我们不能自称提出这个词，也不能只做其中任何一层。
  2. 在本轮检索范围内（关键词 + 近一年 + 若干相邻概念），现有工作的对象多为「已是结构化或合成的输入」（S2/S1/E8）或「抽取 / 合成质量」（S4/E4）或「人工量表」（S5）。「从真实医院扫描件起、把每个准备动作的作用分开量」这一组合，本轮检索未命中同形工作——这是待核缺口，不是「证明无人研究」。下一轮必须补：相邻概念（data readiness / clinical NLP preprocessing / 信息抽取评估）、前后向引文追踪、以及不止近一年的时间窗。
  3. 三个必须避开的坑：
  • HoloBench（S3）已占「聚合随规模退化、max/min 抗退化」——我们的队列级观察要写成复现与延伸。
  • S1 已给出「表示选择对 QA 与 ML 影响相反」的强证据——不能笼统写「结构化更好用」，必须分任务类型说，并解释与它的差别（它比「结构化→叙述」，我们比「扫描件→可用数据」）。
  • S1 还给出「检索归因」与「预算敏感性」两件现成工具（无检索基线、token 预算扫描）——我们已把它们列入待做；若不采用需说明理由。

系统与验证

下面是目标结构，不等于已实现。组件状态分成「代码存在 / 离线测试通过 / 有历史运行 / 端到端验证」四件事。

问题

真实医院的病历是扫描 PDF，不是数据库。要让它们成为「现成的 AI 能直接用」的东西，中间必须做一系列准备动作（把版面读成行、统一单位、标上来源、排好时间、写清字段含义……）。问题分两层：

  1. 差异层：AI-ready 与常规做法（不做准备，或按治理规范做常规准备）的本质区别是什么？好处落在哪个维度上？
  2. 设计层：把准备工作组织成可调用、可核验、可复用的系统（Harness），由 Agent 编排调用，能不能在真实任务上带来可测量的改善？

不预设准备动作总带来正收益。 现状是：AI-ready 更多是标签或人工等级量表；现有的对照实验多在「已经结构化」的输入上做。我们检索范围内未见同形工作，这是检索覆盖内的待核缺口，不是「无人研究」的证明。

目标使用者与使用场景

  • 直接使用者：需要从真实病历里取事实与统计的研究者（临床研究者与数据整理者），不是终端患者，也不是实时临床决策者。
  • 初步场景：科研资料整理与核验——给定一份或一批病历，取回一个事实、一张表或一个计数，并给出依据与未决状态。
  • 候选任务（待任务设计与师兄反馈；不能写成已临床验证的需求）：
  • T1 单病例事实与时间整理：某项目的极值、超阈值次数、某事件的最早/最近日期。
  • T2 跨病例筛选与统计：一批病例里有多少例满足某个条件。
  • 下游消费者：没参与建库的现成 AI / Agent，一次调用或多步调用（方式待定）。

整体架构

目标结构，不等于已经端到端实现。

科研资料整理 / 核验任务
          ↓
Agent：理解任务、选择步骤、在预算内编排
          ↓ 调用
Harness：文档读取与定位、提取与规范化、时间与来源关联、
         检索与分页读取、程序计算、格式与内容核验等可调用能力
          ↓
可复用数据产物与访问接口
          ↓
后续任务使用 → 答案 / 表格 + 依据 + 未决状态

旁路：评测器检查任务是否通过，并独立记录资源代价与失败。

角色分开，但不要求建立多个 Agent（可以复用同一基础模型或同一进程）：

  • 准备流程 Agent：把原始文档变成可复用产物。
  • 下游任务消费者：使用产物完成任务并给出依据。
  • 自动实验驱动器：按协议跑条件、做自检、产出只含聚合数字的结果。

复用的含义必须可检验：跨病例、跨未见任务复用同一套组件，减少逐题定制；准备阶段不得读取留出题目或其答案。

候选消融：多层级处理

已有实现是一条严格超集链：生数据 → 格式统一 → 单位归一 → 溯源与状态 → 机器说明书 → 纵向时间轴。每个版本保留上一版全部内容、只加一样东西。

归因的限度（重要）：超集构造消除了「换了别的东西」这一类混淆，但不足以把差异唯一归因于单一组件。至少还有三个未被控制的量会同时变化——输入总长度 / 材料总量、预计算与物化的程度、提示长度。因此：

  • 超集差值只能读作「在这一串构造下，加上这一样之后结果如何」，不能读作「这一样单独值多少分」。
  • 要支持组件级归因，至少还需要反向拆件（从最完整版本逐样拿走）与长度/预算匹配的控制条件；这些尚未做。
  • 若准备材料里含与测题直接对应的预计算摘要，必须写明这是「预计算 / 物化」的成本收益，不是模型推理能力的提升。

定位：这是用来选择性解释组件作用的候选拆解，不是论文必须成立的结论序列，也不预设每层正收益；层数本身不是贡献。固定准备策略，不得读取留出题目或其答案来定制材料。

已有探索性结果（2026-09-19，results/2026-09-19_ladder.md）：批次 984 例 / 5,255 文档；病例级 12 例 × 11 题 × 9 条件 × 3 次重复，消费者与建库过程无关（建库为零模型机械脚本）。生数据 61.6% → 机器说明书 73.0% → 纵向时间轴 81.9%，前四层单独看几乎不动分。这些数字是探索性结果，只用来支撑「分层归因这个做法可跑通」，并带着上面那条归因限度一起读。
