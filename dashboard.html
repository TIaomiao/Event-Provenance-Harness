1. 研究问题

研究自然语言取数要求能否被正确解释并执行——在纵向 EHR 记录上选出任务真正需要的记录集合、时间点与来源，并如实交出未决状态

本节是给读者（含师兄）的短说明；执行规则与详细状态见 AGENTS 与 CONTROL_PANEL。

两条记录的说明性例子（合成，非实测失败）：同一位患者有两条同一项目的记录，一次落在相对日 0、一次落在相对日 5。问「相对日 0 当天或之前、时间上最靠后的一条」，答案是相对日 0 那条；问「相对日 0 之后最早的一条」，答案换成相对日 5 那条；问「相对日 0 到 5 之间全部」，两条都要给。记录表一个字没变，问法一变，正确答案就变。 此例为合成说明，不代表任何实测结果。

2. 实际比较与结果

逐行原文：只给相关页面的逐行文字，没有按化验记录成组。记录表：同样页面，已整理成一条条记录（含值、单位、两个时间）。 直接选择：模型自己挑记录。先给条件再执行：模型只翻译出条件（时间角色、时间窗、取最近/最早/全部），由同一个固定程序取数。

本次运行：10 对患者包（每个任务同时给出目标患者与另一位病人的材料）、60 个任务 × 两种形态 × 两种解法 = 240 条（2026-10-13）。任务点名目标患者，每块与每行都标注所属患者。

四句话读完：① 把负荷提上去，形态差异出现了，而且翻转——单患者时逐行原文略优（5:1、8:2），两患者时记录表以 32:1 反超。② 机制是记录组装：未整理形态把两患者未成组的原文拼成了并不存在的记录（25 次）；整理形态的失败集中在窗口边界（窗口外 9 次）。③ 整理成表输入的 token 约为 1/48、费用约 1/34。④ 先给条件再执行仍是集合口径满分（两形态都 60/60）。

研究结论：把负荷提上去（每个任务多给一位患者的材料）之后形态差异出现，而且是翻转：单患者时逐行原文略优（5:1、8:2），两患者时记录表以 32:1 反超（联合口径 53/60 对 22/60）。机制是未整理形态把两患者未成组的原文拼成了不存在的记录（25 次），整理形态的失败则集中在窗口边界。整理成表解决的是「记录能不能被正确组装」，不是「选哪个时间点」。先给条件再执行仍是集合口径 60/60。 前两轮「无差异」得到解释：不是整理无用，而是单患者、小体量下题目太轻。但结构仍未与长度分离（逐行原文约为记录表输入的 48 倍），需要等长填充对照臂才能分开。

上一轮（2026-10-06，条件由宿主显式声明）要分开读：直接选择 120/120； 先计划再执行 当时 110/120、修正后离线重放 120/120（重放不是新的模型运行）。

3. 关键边界

  • 记录来自整理后的记录表（规则/OCR 抽取并经校验），不是人工核对的原文事实；10 对包全是开发集，患者级统计功效很弱。
  • 30 题参考是空集、30 题有答案；并列导致的「未决」参考在 10 个包里没能构造出来，仍未覆盖。
  • 逐行原文约为记录表输入的 48 倍，形态差异里结构与长度仍未分离，需要等长填充对照臂才能分开。
  • 「先给条件再执行」的状态由执行器产出、契约不含状态，因此它只报集合口径。
  • 方法与供应商无关性未被证明；来源事实人工核对尚未完成。

参考等级：规则/OCR 派生的选择参考（冻结记录表上按定义独立计算），人工原页核对尚未完成。

4. 下一步与师兄判断

当前检验问题：既然负荷一变形态差异就翻转，那么把「结构」与「长度」分开、并继续提高负荷之后，记录表的正确性优势会保持还是消失？

真实执行状态：负荷条件已跑完（240 条）；记录表以 32:1 反超，但结构与长度仍未分离。仍未运行：记录表 + 等长填充的对照臂：用来把结构与长度分开；并列导致的未决参考：10 个包里没能构造出来——不填预期成绩。

需要师兄判断：

  1. 是否补一条「记录表 + 等长填充」对照臂，把「结构有用」与「输入短有用」分开——这是把结果写成主表结论前最关键的一步。
  2. 是否把「整理成表解决记录组装、不解决时间点定位」作为主表的核心结论，并据此重新定位 AI-Ready 的主张。
