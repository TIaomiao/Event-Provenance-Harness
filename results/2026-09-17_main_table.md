## 二、三条结论

**结论 1：引用可解析这一列，谁都满分，分不出系统。**
三个模型设置、4090 行、引用 100% 全部能解析到真实存在的行。
这正好是现有临床抽取评测报的那个指标（ACIE 报 hallucinated reference 0.0%）。
→ **它已经饱和了，不能用来区分系统。**

**结论 2：真正能分开系统的是"时间落地"和"行数恢复"。**

时间接地（报出的时间逐字出现在它自己引用的那条时间行里）：整病例 **58.6%**，同类合并和逐文档都是 **100%**。
同一个模型、同一个输出上限、同一批文档，**只是换了上下文范围**，就差这么远。

失败的 538 行（41.4%）分两类，逐行查过：

| 类型 | 行数 | 查证结果 |
| --- | --- | --- |
| 完整时间**就在它自己引用的那行里**，只是被改写格式 | 74（14%） | 比如把 `2023-12-02 08:15:33` 写成 `2023/12/2 8:15:33` |
| **整条时间戳在文档里对不出来** | **464（86%）** | 日期在文档里有、`时:分` 也在文档里有，但**这个"日期+时分秒"的组合在任何一行里都不存在** |

**没有一行是"日期凭空编的"**——464 行的日期全部能在病例里找到。
最可能是模型**把分开的日期格和时间格拼成了一条时间戳，并补上了秒**。

同时，这 464 行的引用可解析率仍是 **100%**。
→ **引用存在性检查看不见这一类错。**这是本表最有价值的一格。

⚠️ **口径提醒**：这一格的准确说法是"报出的时间戳无法在文档里作为整体找到"，
不是"报了不存在的时间"。我第一版写成后者，是错的，已更正（见第七节）。

行数恢复：41% / 52% / 64%，没一个到 100%。

**结论 3（撤回旧结论）：之前"13% 的数值在全文找不到"是我自己造的假象。**

`max_tokens` 从 8000 提到 16000，同一个病例、同一个提示词：
CASE-05 的值接地 77% → 80~100%，"找不到"的数 18 → 0~18（跑 3 次跳）。
所以那个 13% 是**输出上限太低**造成的，不是模型编数字。

本次 12 病例、三个上下文设置、**3926 个值**重新测：

- 逐字接地 82.4~85.2%
- 按数值归一化（去尾零、统一分隔符）后 **98.9~99.8%**
- **逐字不接地的 633 处，没有一处是"整份病例里连子串都找不到"**（0 处）

633 处逐字不接地，全部能在**模型自己引用的那份文档**里找到来源：

| 差异类型 | 数量 | 出现在 |
| --- | --- | --- |
| 尾零 / 小数位不同 | 421 | 自己引用的文档 |
| 千分位、空格等格式差异 | 163 | 自己引用的文档 |
| 前导零 | 48 | 自己引用的文档 |
| 前缀截断 | 1 | 自己引用的文档 |

其中 **21 处（占 3926 的 0.5%）在整份病例里找不到数值相等的数字**，只是在同一份文档里以"更长数字的子串"形式出现（相当于取整或截断）。其余 612 处都能找到数值完全相等的数字。

→ **值这一层没有编造；编造发生在时间这一层。**

## 三、稳定性：这一列必须多跑几次

同一配置跑 3 次（同类文档合并，CASE-05 + CASE-01，温度 0）：

| 指标 | 3 次结果 | 波动 |
| --- | --- | --- |
| 引用可解析 | 100% / 100% / 100% | **0** |
| 时间接地 | 100% / 100% / 100% | **0** |
| 输出行数 | 253 / 252 / 255 | 3 行 |
| **值接地** | **95% / 95% / 84%** | **11 个点** |

→ **引用和时间这两列可以报单次；值接地必须报区间或多次平均。**
这是本次测出来的，之前那版"3 病例 × 3 次"也看到过同样的现象（值 80~100%、行数零波动）。

## 四、结构性真值怎么来的（卡点 3 解决）

不再用"数序号列"或"数数值形状"这两个估计。改成**按值列做几何聚类**：

1. 每页把格子的横坐标做直方图，连续密集的 bin 算一列；
2. 值列 = 那一列里 ≥60% 是纯数字、且位置在页面中右部（这样序号列不会被选中）；
3. 行距 = 相邻值格的纵坐标中位数；
4. **行数 = 值格按半行距聚出来的簇数。**

12 病例结果 2518 行。模型跟它基本对得上（CASE-05：几何 139 / 模型 141；CASE-06：几何 330 / 模型 315；CASE-09：几何 293 / 模型 291）。

75 个"没找到值列"的页不是漏行：那些页平均 50 个格子、只有 4% 是纯数字，是纯文字页。

## 五、还没解决、需要师兄点头的（卡点 5）

1. **主表的行列就按上面这样定，行不行？**行的顺序：规则 → 整病例 → 同类合并 → 逐文档。
2. **"行数恢复率"拿几何真值当分母**。它不是医生金标准，能不能当主指标之一？还是只当辅助？
3. **值接地噪声 11 个点**。论文里报区间、报多次平均、还是干脆换成"数值归一化后"的口径？
4. **"系统级失败"要不要单列一列。**现在"吐不出 JSON"的病例被算进行数里，等于把"系统根本跑不出来"伪装成"少抽了几行"。
5. 目前只做了 16 张事件表里的 **1 张**。剩下的表要不要一起进主表。
