## 二、四个时间角色都存在且带明确标签

每页页脚均有：**采集时间 / 接收时间 / 报告时间 / 打印时间**（各 1 条），另有审核者。

→ 与研究卡 v0.4 的 `sampling / report / record / document` 四角色逐字对应，映射关系：
采集时间 = sampling，报告时间 = report，接收时间 ≈ record，打印时间 = document。

## 三、这对论文意味着什么（E1 金标准是现成的）

**任务**：给定一位患者的文档集合，问"这个项目被独立测量了几次"。

| 系统的默认数法 | 得到的答案 |
| --- | --- |
| 每份报告算一次 | **11** |
| 每个检验项目行算一次 | 几百 |
| **按采样事件算（正确）** | **2** |

**这个错误不体现在任何值级指标上**：所有数值都可以抽对，而"测了几次"错了 5.5 倍。

**下游后果可计算**：复测间隔（12-02 → 12-10 是 8 天，而不是"同一天测了 7 次"）、趋势斜率、跨科室报告计数。

**归并依据是数据里真实存在的**：采集时间精确到秒，同一采血的 7 份报告落在 14 秒内；不同采血相隔 8 天。金标准**不需要人工判断**，可从采集时间直接导出——**这是最强的可用性**。

## 四、嵌套 Harness 的职责（与师兄的主轴对齐）

| 层级 | 职责 |
| --- | --- |
| **内层**（单份报告） | 重建表格、抽取 项目/缩写/结果/单位/参考区间/检测方法，并绑定**四个时间角色**（关键是不要用报告时间冒充采集时间） |
| **外层**（跨报告） | 用采集时间邻近性 + 标本类型 + 项目集合，把多份报告归并成**采样事件**；输出事件数、误合并率、误拆分率 |

**"为什么必须嵌套"**：内层只需要单份文档，外层必须有全部报告的视野。单层平铺的 agent 在信息上无法同时做好这两件事。

## 五、今天犯过的四个错误（记录以备再犯检查）

| # | 错误 | 根因 |
| --- | --- | --- |
| 1 | 把 107 个"只出现一次的 6 位串"判为行级标识 | 把**频次口径**当成**坐标证据** |
| 2 | 在 `case_demo_output/` 上分析，却以为那是面板的数据 | 没核对面板的 `--run-root` |
| 3 | 把 7/8/10 位"码"当成临床编码 | 那些是**被脱敏涂抹的字段**，未与 `redaction_hits` 比对 |
| 4 | 断言"文档没有采集时间" | 脚本输出**截断了一列**，把"没显示"读成"等于零" |

**共同根因**：用间接信号下结论，不核对真实产物。**与"假模型"事故同源。**

**新增执行规则**：
1. 任何"某字段不存在"的结论，必须在**完整输出**上确认，不得依据被截断或经过筛选的输出。
2. 任何关于"数据里有什么"的结论，必须先确认**数据来源路径**（面板根目录 vs 演示目录）。
3. 任何"编码/标识"的结论，必须先与 `redaction_hits` / `residual_scan_hits` 比对，排除脱敏残留。
