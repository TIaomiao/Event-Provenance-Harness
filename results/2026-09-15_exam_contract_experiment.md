# 实验 E-A/E-B/E-C：用现有病例级试卷契约考模型（2026-09-15）

## 一、为什么做这个

导师（师兄）指出：最基础任务的输入输出没有完全定义下来，所有 idea 必须在固定的输入输出上跑才有可比性，benchmark 的产物就是论文里最主要的那张表。

核查后发现：**流水线里其实已经定义好了，而且比"PDF 转键值对"完整得多。** 我们论文这边一条都没接上去。

| 项 | 内容 |
| --- | --- |
| 试卷 | `lung_cancer_ehr_standard_exam` 肺癌 EHR **病例级**标准试卷 v0.2 |
| 输入 | 一个病例的脱敏文档集（多份 PDF 的 OCR 结果 + bbox + 文档类型） |
| 输出 A | **49 个标量问题**，每条答案必带 `answer_status` / `source_refs` / `validation_status` / `quality_flags` 等 9 个字段 |
| 输出 B | **16 张事件表**（含 `laboratory_observations`），每行必带来源引用与状态 |
| 状态码 | **9 种**：observed / not_mentioned / source_document_absent / not_applicable / ocr_failed / parser_failed / conflicting / redacted_unrecoverable / unknown |
| 模型 IO 契约 | `clinical_model_io.schema.json` |
| 金标准 | 已冻结（v0.30，2026-08-17，125 条 = 85 标量 + 40 检验事件，5 例），**但医生审核结果尚未回收**；`api_ready=false` |

## 二、实验设置

- 病例：`CASE-05`，16 份文档、15 种文档类型。
- 输入规模：146,798 字符（约 10.7 万 OCR 行 token）。
- 在 Larry 上执行，只有 prompt 出网；脚本经 stdin 送入，服务器零写入。
- 单次成本 &lt; $0.05。

## 四、四个发现

**发现 1：格式不是难点。** 两个模型都能产出完全符合契约的 JSON（49/49，无缺字段），引用的文档 id **100% 真实存在**。

**发现 2：同一份输入、同一套契约，两个模型的状态判断差得很远。** luna 用了 10 次 `source_document_absent`，gemini 一次没用。**这正是导师担心的"不可比"。** 而且这件事**可以机械核验**：流水线知道这个病例有哪些文档类型（本病例 15 种），所以"某信息所依赖的文档类型不在本病例里"这个判断，不需要医生就能判对错。

**发现 3：`observed` 的可核验率很低。** gemini 的 31 条 observed 逐条分类：

| 分类 | 条数 |
| --- | --- |
| 值在引用文档里逐字可查 | 6 |
| 值是英文编码（如 male/female，文档是中文）——正常归一化 | 10 |
| 说 observed 但值是空的（自相矛盾） | 4 |
| **值是自由文本，且在整份病例里都找不到逐字匹配** | **11** |

- 没有任何一条是"引用错了文档"（值在别的文档里出现 = 0）。
- **注意**：逐字子串匹配偏严（改写、日期格式化、单位差异都会判失败），11 这个数字是**上限**，不是已确认的幻觉数。需要人工抽查几条才能定论。

**发现 4：同一模型同一输入，两次运行结果不同。** 两次运行在 `coded_norm`（1 → 10）、`grounded`（10 → 6）、`free_text`（12 → 11）上都发生了变化，尽管设置 `temperature=0`。**这本身就是一个必须记录的可复现性问题。**

## 五、这次实验否证了什么

- ❌ "模型读单份文档够准，所以整个病例也应该没问题" —— 在**契约状态判断**这一层上不成立：两个模型在同一份输入上给出了实质不同的状态分布。
- ❌ "用大模型直接当金标准" —— 同一输入两次结果不同，不能作为参考标准。

## 六、这次实验**没有**否证的

- **状态判断的正确率**还未测：需要一个"哪些信息本来就依赖某类文档"的机械判据，这部分不需要医生。
- **11 条自由文本**是否真的编造，需要人工抽查几条。
- gpt-5.6 系列在 13 万 token 输入上超时，**是网关限制还是模型限制**未查明；缩小输入或分批可能可以跑通。

## 七、下一步（按师兄要求：固定输入输出再比）

1. **把主表的列定下来**：49 问正确率（分开报 observed 正确率与**状态判断**正确率）、检验事件的值/时间/来源、漏项、多项、成本。
2. **补上不需要医生的那几列**：`source_document_absent` / `redacted_unrecoverable` / `ocr_failed` 三类状态可以对着流水线元数据（文档类型清单、`redaction_hits`、低置信度行统计）机械核验。
3. **人工只抽查分歧项**，不重做整张卷子。
4. 缩小输入规模，让 gpt-5.6 系列也能跑（本病例 16 份文档一次塞入会超时）。
