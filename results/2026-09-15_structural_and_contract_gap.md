# 结构性真值 + 归一化评分 + 契约缺陷（2026-09-15，第 3 轮）

## 一、结构性行数真值（不需要医生）

检验表最左列是**每页从 1 开始的序号**。数这个 1..n 序列，就能得到"这份报告到底有多少条检验"的结构性估计。

| 文档 | 页 | 序号行数 |
| --- | --- | --- |
| DOC-013 | 1 | 26 |
| DOC-013 | 2 | 26 |
| DOC-013 | 8 | 20 |
| DOC-013 | 9 | 21 |
| DOC-013 | 11 | 3 |
| **合计** | | **96** |

**注意这是下界**：只有 5 页能检出 1..n 序号列，其余 6 页（甲状腺/凝血/输血等报告类型）没有这个列。
所以 96 是"确定存在的行数"，真实值 ≥ 96。

**模型输出 141 行，比值 141/96 = 1.47。**

## 三、四个发现

**发现 1：值级指标是唯一稳定的内容级指标。**
三次运行完全一致：`115/141 接地、8 在别处、18 整篇找不到`。
→ **18/141 = 13% 的行，数值来源不明**，是主表可以放心用的一列。

**发现 2：项目名 / 单位 / 时间的接地率不稳定，因为它们取决于模型把引用停在哪一行。**
引用总数从 402 → 282 → 141（同一输入），说明模型的"引用粒度"每次都不一样：
- 引到含项目名的行 → ITEM 100%
- 引到只含数值的行 → ITEM 0%

→ **这类指标必须改成"容忍度"形式**（例如"值必须出现在同一份文档内"），否则量的是引用习惯而不是正确性。

**发现 3（本轮最重要的 I/O 缺陷）：契约无法表达时间来源。**

| 项 | 数值 |
| --- | --- |
| 模型输出的时间能整篇找到 | **141 / 141** |
| 时间出现在"值所在那一行" | **0 / 141** |

原因：**OCR 后检验表的单元格里只有 项目名 / 值 / 单位，时间在页脚，是页级信息。**
所以一个观测的"值来源"和"时间来源"**必然是两个不同的行**。

→ **`source_refs` 一个字段不够用。事件表必须增加 `time_refs`（时间所在的行）。**
这是导师所说"输入输出没定义清楚"最具体的一条，而且是被实测逼出来的。

**发现 4：OCR 会把单位写坏，单位比对必须先归一化。**
实测原文出现 `mmo1/L`（数字 1 替字母 l）、`m0sm/L`（数字 0 替字母 o）。
不做归一化的单位接地率会变成 OCR 质量的度量，而不是模型能力的度量。
（注：本轮归一化后仍未消除运行间差异，说明主因是引用粒度而非 OCR。）

## 四、对主表与契约的最终建议

| 项 | 结论 |
| --- | --- |
| 值接地率（行级 / 文档级） | ✅ **可复现**（82%），进主表 |
| 来源不明率 | ✅ **可复现**（13%），进主表 |
| 行数比（模型输出 / 结构真值） | ✅ 可算（1.47），进主表；结构真值需再精确化 |
| 项目名 / 单位 / 时间接地率 | ⚠️ 必须改成容忍度形式，否则不稳定 |
| **事件表契约需增加 `time_refs`** | ❗ 必须改 |
| 单位比对需归一化 | ❗ 必须做 |
| 内容正确率 | ❌ 仍需医生 |

## 五、下一步

1. 把结构真值做精确：补齐没有序号列的 6 页（改用"含数值+单位的记录数"估计）。
2. 把 ITEM/UNIT/TIME 接地率改成**文档级容忍度**，重测稳定性。
3. 在契约里加 `time_refs`，并让模型分别引用值来源与时间来源，再测时间接地的真实水平。
