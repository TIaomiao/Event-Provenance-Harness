# 机械核验（不需要医生）的实测结果与它的局限（2026-09-15）

## 一、做法

对每个问题，从流水线元数据推出"哪些状态码是站得住的"，再对照模型答案机械判错：

| 元数据 | 来源 |
| --- | --- |
| 病例有哪些文档类型 | `result.json → category` |
| 每类文档的脱敏命中数 | `deidentified_layout_NOT_SAFE.json → redaction_hit_count` |
| 每类文档的低置信度行数 | `result.json → quality.low_confidence_line_count` |

派生的机械判据：

| 判据 | 含义 |
| --- | --- |
| A | 报了 `source_document_absent`，但依赖文档其实在病例里 → **矛盾** |
| B | 依赖文档不在病例里，模型却没报 `source_document_absent` → 细分 B1/B2/B3 |
| C | 报了 `redacted_unrecoverable`，但那些文档脱敏命中为 0 → **矛盾** |
| D | 报了 `ocr_failed`，但那些文档没有低置信度行 → **矛盾** |
| E | 报了 `observed`，但引用无效 → **矛盾** |

## 二、结果

**病例选择**：池子共 200 例，**78 例没有病理报告、13 例没有检验报告、122 例两者都有**。
刻意选了 7 例（缺病理 3 + 缺检验 2 + 齐全 2），共 **343 条答案**。

| 判据 | 条数 |
| --- | --- |
| 依赖文档类型缺失的问题（机械可判） | **22** |
| **模型正确报出 `source_document_absent`** | **0** |
| A 谎报 absent（矛盾） | 0 |
| B1 报了 observed 且**在别的文档里找到了**（合理） | 7 |
| B2 报 not_mentioned/unknown（**应报 absent，真错**） | **1** |
| B3 报 not_applicable（口径模糊，判不了） | 14 |
| C 谎报 redacted_unrecoverable | 0 |
| D 谎报 ocr_failed | 0 |
| E observed 但引用无效 | 0 |
| 引用有效率 | **100%（7/7 例）** |

**状态码使用情况（343 条答案合计）：**

| 状态 | 次数 |
| --- | --- |
| observed | 233 |
| not_mentioned | 57 |
| not_applicable | 53 |
| **其余 6 种（含 3 类可机械核验的）** | **0** |

## 三、两个结论

**结论 1（稳）：9 种状态码只用了 3 种。**
`source_document_absent` / `redacted_unrecoverable` / `ocr_failed` 这三个**本来可以机械核验**的状态，在 343 条答案里**一次都没出现**。这份病例里明明有大量可触发的证据：`order_execution` 单类文档就有 **873 处脱敏命中**、`surgical_anesthesia_record` 有 **131 行低置信度 OCR**。

**结论 2（对第一步不利）：这条"不用医生"的路，鉴别力比预期弱得多。**
22 个可判断面里，7 条合理、14 条落在 `not_applicable` 的模糊地带、**只有 1 条是确切错误**。
**也就是说，即便模型完全不用这三个状态码，这个维度也只能抓到约 1/22 的错误。**

## 四、对 benchmark 设计的影响

1. **"机械核验状态码"不能作为主表的主要列** —— 鉴别力不够（1/22）。可以作为**附加列**，附上"模型从不使用这些状态"这一事实。
2. **`not_applicable` 的定义必须先收窄**，否则 14/22 的判断都不可判。这是导师说的"输入输出要定义清楚"的又一条具体项。
3. **格式层没有问题**：引用有效率 100%、`observed` 无无效引用、`confidence` 字段模型会填（49/49）。**所以主表的价值不在格式，只能在内容正确率与分层差异上。**

## 五、过程中的一次自我纠正

初次统计时我把 `B=22` 报成"22 个全错"。细分后发现 7 条合理、14 条不可判、**真错只有 1 条**。
**已纠正**。这一条再次说明：`exp_absent` 是"首选文档类型缺失"，**不等于"答不出来"**——信息可能记在别的文档里。

## 六、复现（第二轮，9 例 / 441 条）

第二轮扩大样本并修掉选例重复：9 例（缺病理 4 + 缺检验 1 + 齐全 5），文档上限 12 份。

| 判据 | 第一轮（7 例 / 343 条） | 第二轮（9 例 / 441 条） | 合计（16 例次 / 784 条） |
| --- | --- | --- | --- |
| 依赖文档缺失（机械可判） | 22 | 21 | **43** |
| 模型正确报 `source_document_absent` | 0 | 0 | **0** |
| A 谎报 absent | 0 | 0 | **0** |
| B1 在别的文档里找到了（合理） | 7 | 9 | **16** |
| **B2 真错** | 1 | 4 | **5** |
| B3 报 not_applicable（不可判） | 14 | 8 | **22** |
| C 谎报脱敏 / D 谎报 OCR / E 无效引用 | 0 / 0 / 0 | 0 / 0 / 0 | **0** |
| 引用有效率 | 100%（7/7） | 100%（9/9） | **100%（16/16）** |

**状态码使用（784 条答案合计）**：observed 534、not_mentioned 140、not_applicable 110；
**其余 6 种合计 0**。

**复现后的三条结论：**

1. **格式层零缺陷，且可复现。** 16 次运行、784 条答案：每例 49/49 齐全、引用有效率 100%、`observed` 零无效引用、`confidence` 字段必填。
2. **9 种状态码只用了 3 种，两轮完全一致。** 3 类机械可核验状态（absent / redacted / ocr）**使用次数为 0**。
3. **机械核验的确切错误率 5/43 ≈ 12%**（另 16 条合理、22 条落进 `not_applicable` 模糊区）。
   **鉴别力不足以支撑主表的主要列。**

**成本**：16 次运行 × 约 13 万输入 token ≈ 210 万 token，合计约 **$0.6**。

## 七、对主表设计的最终影响

| 列 | 能否用 | 依据 |
| --- | --- | --- |
| 格式合规率 | ✅ 可用，但**已无鉴别力**（全是 100%） | 16/16 全满 |
| 引用有效率 | ✅ 可用，但**同上**（100%） | 16/16 全满 |
| **状态码使用分布** | ✅ **有鉴别力**：9 种只用 3 种，两轮一致 | 784 条 |
| 机械可判错误率 | ⚠️ 只能当附加列（约 12%，且 22/43 不可判） | 43 条 |
| **内容正确率** | ❌ **无金标准做不了**，必须等医生 | 已冻结 125 条待回收 |
| 数值容差、证据定位 PCK | ⏳ 未测 | 待做（第 2 步） |

**下一步（第 2 步）**：写事件表评分器 —— 16 张表的值/单位/时间/来源，这部分**大部分可以机械核验**（引用的行是否真的含该值），不需要医生。
