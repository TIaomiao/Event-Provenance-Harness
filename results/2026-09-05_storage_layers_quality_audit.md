# EHR 产物位置、数据层次与质量检查

日期：2026-09-05。范围：Larry 上既有 EHR 产物目录、处理源码、200 份 result.json 的白名单元数据，以及一份既有匿名就绪报告。

状态：只读检查完成；未搬迁数据、重跑 OCR、调用临床模型、重启服务或读取病历正文到对话。

## 1. 目录位置与空间

当前 pilot_output 和 Larry 的 data 目录位于同一个 /home 文件系统，设备号相同。文件系统容量约 51 TiB，使用约 39 TiB，可用约 13 TiB；du 显示 pilot_output 约 190 GiB，private_manifests 约 648 MiB。数值为查询时的近似值。

将运行产物移到 data 更适合长期管理：代码仓库、依赖环境与大规模派生数据分开，减少目录索引、同步、备份和误操作负担。但在相同文件系统内移动目录不会减少总磁盘占用。文件条目数也不能替代容量统计；此次 df -i 未提供可解释的 inode 使用统计，不能据此判断 inode 是否紧张。

建议后续为 EHR 派生数据设置独立的数据根，原始 PDF、L1、L2、模型运行产物按职责组织。迁移安排在批次安全断点，先检查状态文件和脚本的路径绑定、符号链接与权限，保存可回退入口，再切换。当前未执行迁移；本次质量检查期间文件数仍有小幅变化，不能把目录当成冻结快照直接搬动。

同一份 PDF 会生成多种产物；目录中还包括历史重跑、辅助文件与备份。以下是固定文件名的实际条目计数，不是独立患者数，也不是去重后的 PDF 数。

另有复核材料、图片资产、状态及备份文件。检查时尚在产生增量，后续抽样遍历看到的 result.json 数量为 341,000。因此不能把不同时间的计数差异解释成丢失或重复错误。

L1 已做 OCR，但仍含敏感文字。L2 做过自动脱敏规则处理，仍是候选；命名与元数据明确要求进一步复核。全量输出不等于已完成文档级语义解析 L3 或病例级纵向结构化 L4。

## 3. 200 份输出的元数据抽查

抽样方式：对 pilot_output 下 result.json 的相对路径使用固定种子前缀 20260905 和 BLAKE2b 哈希，选最小的 200 个，覆盖两个顶层输出组。样本遍历仅收集路径；读取时只统计固定白名单元数据，不输出正文、字段值、真实路径或文档标识。由于目录仍变化且存在历史产物，这不是冻结临床评价集，也未声称按病例独立抽样或按文档类别均衡抽样。

| 项目 | 本次观察 |
| --- | --- |
| 元数据可解析 | 200/200，合计记录 1,019 页 |
| L1 与 L2 文件存在，bbox 标志保留 | 200/200 |
| schema | 199 份为 1.0，1 份为 0.9 |

| api_ready / deidentification_complete / case_level_structuring_complete | 样本中均为 false |
| 类别解析状态 | 168 份 category_parser_pending，32 份 prototype |

| OCR 行数及置信度 | 81,854 行；低于 0.8 的 2,940 行，低于 0.6 的 720 行 |

低于 0.8 的行约占 3.59%，低于 0.6 的约占 0.88%。这只是 OCR 模型的置信度提示，不能据此宣称字符准确率约 96.41%。高置信度文字仍可能错，文字正确也可能存在行列错配。

164/200 是当前自动规则的通过情况，不能称为脱敏准确率。36 份隔离可能同时含真实残留和误报，需在适用的小样本任务中区分。本轮没有合并独立人工审核状态，因此这些自动字段不能证明所有文档都未被人工看过。

199 份没有生成复核 HTML，与全量运行的 JSON 输出模式相符，不能当作 OCR 缺失。L1/L2 文件配对和状态字段能说明处理链已有产物，不能证明所有 bbox、文字、时间或检验行都正确。

既有匿名就绪报告的文件时间为 2026-08-30，记录标准试卷仍为部分解析覆盖、当时无真实双模型返回和完整临床金标准。它仅作历史背景，本轮没有把旧报告当作当前全量运行状态。

## 4. 与首轮论文直接相关的时间问题

源码调用链显示：

- gpu_hybrid_ocr_batch.py 的 _process_recognized 逐 PDF 向 process_extracted_pages 传入该文档页面。
- ehr_pipeline.py 的 _relative_date_context 只根据传入文档中的日期选取锚点；当前逻辑从距最晚日期 400 天以内的日期中取最早日期。
- ehr_pipeline_v1_0.py 的 activate 覆写脱敏/扫描规则，未加入病例统一时间锚点。
- build_partial_case_answer.py 的 _append_event 沿用源记录 relative_time / relative_day；本次核查的装配链未完成跨文档重基准。

所以两份文档分别写“相对日 0”，其起点可能不同，不能直接判定同日。该结论来自实现逻辑；本轮没有读取真实日期来估计受影响比例。

对当前重复检验任务，优先核对并补一个小范围的共同时间接口：在 Larry 从既有 L1 提取允许使用的时间元数据，核对原有局部锚点，生成文档到病例时间轴的偏移，再输出研究所需的统一相对时间。身份与绝对日期继续留在受控位置。缺少可靠时间依据时保留 unknown，不推算或补造。

这个适配尚未实现。需要先用合成例子、再用获准的小样本核对；可以复用既有 OCR 与证据引用，不必为此重跑全量 OCR。若短期仍不能保证跨文档时间一致，可先在同文档内的重复检验任务调试评分器，再扩展跨文档范围。

主对照的两组应共享同一合法时间表示与可见证据，避免仅改善一组输入造成不公平比较。若研究时间归一算法本身，则单独设置评价与对照；当前自家管线不足不能直接当成已证实的文献创新点。

## 5. 当前对论文的用途

现有 L1/L2 是可复用的真实证据基础，可支持选择小型研究样本、构造重复事件任务、保留来源定位，以及后续不同文档类型与规模下的压力测试。

下一步先从允许使用的检验记录中形成研究切片，补齐共同时间、少量可信参考答案和评分；再比较直接抽取与证据组织后的模型输出。190 GiB 产物不要求全部进入第一轮实验，也不等于论文已有同规模标注集。

结论置信度：目录/层次/源码时间逻辑为高；整体提取准确性、脱敏召回率和论文方法收益仍未知。主要反例与替代解释包括高置信度错字、规则漏检/误报、表格错配、局部时间起点不同，以及历史重跑造成文件计数重复。需要任务级参考答案和受控小样本核对才能进一步评价效果。
