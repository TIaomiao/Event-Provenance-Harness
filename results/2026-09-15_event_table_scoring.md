# 事件表评分器：laboratory_observations 的机械评分（2026-09-15）

第 2 步。目标：在**不需要医生**的前提下，对 16 张事件表之一（检验观测）做内容级评分。

## 一、做法

- 输入：CASE-05 的检验报告文档（1 份、1,390 OCR 行）。
- 要求模型输出 `laboratory_observations`，字段按试卷契约（`event_id` / `relative_time` / `answer_status` / `source_refs` / `extraction_method` / `confidence` / `validation_status` / `quality_flags` + `test_name` / `test_code` / `value_numeric` / `value_text` / `unit`）。
- **关键设计：引用必须到行级**，格式 `DOC-xxx:L<n>`，且明确要求"不要引用不含该值的行"。
- 评分全部机械完成：把每行的值 / 项目名 / 单位 / 时间拿去和**它引用的那一行**逐字比对。

## 四、三条发现

**发现 1（正面）：这个指标有鉴别力。**
与状态码那类（全部 100%、无区分度）不同，值接地率有真实分布：**82%**，并且**两次运行完全一致（115/141）**。可以作为主表的一列。

**发现 2（负面，且重要）：单位接地率被 OCR 噪声污染，不能直接当指标用。**
第二次运行单位接地率掉到 **0%**。原因是 OCR 把单位写坏了——实测原始文本里出现 `mmo1/L`（数字 1 替字母 l）、`m0sm/L`（数字 0 替字母 o）。
模型若输出修正后的 `mmol/L`，就与原文逐字不匹配。
**所以单位必须做归一化后比对，否则这个指标量的是 OCR 质量而不是模型能力。**

**发现 3（必须记录）：同一模型同一输入，两次运行差异很大。**
引用总数 543 → 282、单位接地 100% → 0%、时间从"未输出"变成"输出但未命中"。
设置 `temperature = 0` 也未能消除。**这是继 09-14 那次之后第二次观察到同输入不同输出，必须写进论文的复现性说明。**

## 六、下一步
