# 契约缺陷实测：加 `time_refs` 把一个不可测维度变成稳定可测（2026-09-15，第 4 轮）

## 一、结构真值：两个独立估计（不需医生）

| 估计方式 | 数值 | 说明 |
| --- | --- | --- |
| `index_based` | **96** | 数每页 1..n 序号列（只有 5 页有该列）→ **下界** |
| `value_like` | **161** | 数"形似结果值"的记录（小数、或不属于序号序列的整数）→ **上界估计** |
| 模型输出 | **141** | 落在两个估计之间，量级合理 |

## 三、发现

### 发现 1（本轮最重要）：`time_refs` 把一个不可测维度变成稳定可测

| | 加 `time_refs` 之前 | 加 `time_refs` 之后 |
| --- | --- | --- |
| 时间接地率 | **测不出来**（0/141，因为时间与值必然不在同一行） | **142/142，三次稳定** |

原因（实测）：OCR 后检验表的单元格只有 项目名 / 值 / 单位，**时间在页脚，是页级信息**。
一个观测的"值来源"和"时间来源"**物理上位于不同的行**，单个 `source_refs` 无法表达。

→ **这是"输入输出要定义清楚"最有说服力的一条证据：一个字段的改动直接解锁了一个可测维度。**

### 发现 2：契约还缺第二个引用字段（或需重定义 `source_refs`）

`source_refs` 被定义为"含结果值的那一行"，于是：
- 项目名在引用**行**里的命中率 **恒为 0**（0/142、0/142、0/141）
- 项目名在引用**文档**里的命中率 **142/142**

两条修法：
- (a) 增加 `item_refs`；或
- (b) **把 `source_refs` 重定义为"这条观测所在的表格行/页"**，而不是"含值的那一行"。

**(b) 更干净**：观测的粒度是"一行检验记录"，引用就该指向那一行的证据集合，而不是某一个单元格。

### 发现 3：容忍度能提高稳定性，但不能消除漂移

- 文档级 > 行级（项目名 0% → 100%）
- 但值的行级接地仍在 115–137 之间漂移，说明模型的**引用粒度每次不一样**（引用总数 402 / 282 / 141）

→ 主表的接地类指标**必须声明容忍度层级**（文档级 / 页级 / 行级），否则数值不可比。
