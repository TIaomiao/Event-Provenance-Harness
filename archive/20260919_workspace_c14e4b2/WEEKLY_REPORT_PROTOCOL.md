# 每周汇报协议（给师兄）

目的：每周 3 分钟口头讲清 + 一页纸交付。**不是汇报"做了多少"，是汇报"知道什么了"**。

## 一、固定五段（顺序不要改）

| 段 | 内容 | 时长 |
| --- | --- | --- |
| 1 | **一句主张**：这周我的主张有没有变？没变就说"没变" | 15 秒 |
| 2 | **一个新数字**：本周唯一的新数字 + **它是怎么来的**（命令 + 输入是什么） | 60 秒 |
| 3 | **一个失败/反例**：本周哪里错了、哪条路不通 | 45 秒 |
| 4 | **下周一件要事**：只讲一件，不列清单 | 30 秒 |
| 5 | **一个要他决定的问题**：必须是"你不决定我就卡住"的那种 | 30 秒 |

## 二、硬规则（针对 2026-09 这次教训）

1. **每个数字必须能追到一条可重跑的命令**，且输入不能是手写的。做不到就不许说这个数字。
2. **`calls = 0` 的结果不许称为"模型结果"或"进展"**。合成自洽检查只能叫"代码自测"。
3. **每周至少报一个失败或反例**。一周全是好消息，说明这周没做真实验。
4. **不许把状态文件里的限定语（"合成""不可外推""待核对"）在汇报时删掉**。删限定语 = 造谣。
5. 汇报材料里的每个数字都要能指回 `results/` 下的一个文件。

## 三、正例 / 反例

反例（这次踩过的坑）：
> "本周完成了事件候选生成，F1 从 0.6667 提升到 1.0，source_support 从 8/12 提升到 12/12。"

问题：这些数字是手写 JSON 对手写 JSON，模型调用 0 次，输入不是真实材料。听起来像进展，实际是自测。

正例：
> "本周第一次用真实模型跑了一份真实检验文档。命令是 `python src/prototype/flat_baseline.py --doc CASE-02/doc-007`，
> 输入是服务器上那份 OCR JSON。结果：项目名 6/10 对、值 9/10 对、采样时间 2/10 对、来源支持 3/10。
> **值和项目基本能抽对，但时间几乎全错**——模型把页脚的打印日期当成了采样时间。
> 下周我要确认这是不是所有文档的通病。需要你决定：能不能给我 20 例的授权，我要看这个比例是否稳定。"

## 四、给师兄的四个固定问题（每月问一次）

1. 我们要投的赛道确定了吗？（KDD 2027 Cycle 2 官方日期至今未公布）
2. 模型预算和供应商怎么走？我已经算出主实验的量级，但需要单价才能报价。
3. 20–50 例的分层开发集授权，什么时候能到位？
4. 你说的"嵌套 harness"，最接近哪篇论文的图？我需要对标。

## 五、什么时候可以说"这个方向要改"

当**同一个失败连续两周无法解释**，或**闸门判据明确不成立**（例如 OCR 原文里根本没有采样日期）时，主动提出改方向，并附上你试过的三条路和各自的失败点。**主动叫停比硬撑到死线更有价值。**
