## 推荐：3 个持续 session

| Session | 运行位置 | 主要职责 | 交付 |
| --- | --- | --- | --- |
| A 研究总控与汇报 | 本地 Intern，本次对话可继续承担 | 任务范围、协议版本、参考论文、实验解释、向师兄汇报；按需只读检查远端与其他任务结果 | 一页研究卡、统一协议、汇报提纲 |

| C 评测与错误分析 | SSH 到 Larry，同一 EHR 项目下专用评测目录 | 任务格式、参考答案管理、评分脚本、结果表与错误归类 | 小型开发参考集、评分器、对照结果表、代表错误 |

zian 的实习目录保留为会议上下文入口，录音归档后由总控检索与读取相关片段。第一周不需要额外设置一个持续会议整理或文献 session；临时文献核查可由总控短时委派。

本机 app 项目列表已确认存在本地 Intern、远端 Larry 的 LabelSystem 和远端 zian 项目。两种访问身份不代表需要分两套 EHR 数据与代码。

## 运行端、端口和目录

- 本地/SSH 决定工具命令在哪台机器执行；如果 SSH 到服务器后由 Codex 工作，模型推理是否本地运行仍取决于模型配置，不能由 SSH 推出。
- 第一周采用文件与命令行实验，不需要为三个 session 各建一个网页服务端口；沿用现有 SSH 连接。
- B/C 的实验代码与结果应使用独立目录；原始数据沿既有受控位置由获准程序读取，对话只返回匿名统计、结构或合成例子。
- 此前在 EHR 子树执行 Git 文档跟踪查询结果为空，因此暂不能假设普通 Git worktree 会携带该子树。开隔离 worktree 前先核实跟踪范围；首轮可在专用实验目录按文件归属隔离。
- 单纯新开 session 不提供文件写入隔离。B/C 不应同时修改共享契约、同一个源码文件、同一个结果文件或全局运行状态。

## 先固定共同接口，再并行

1. A 与用户写一页任务卡：允许输入、目标输出、正确性定义、第一轮比较的一个变量。
2. 将定稿协议以版本化文件放在 B/C 都能读取的实验文档位置；本地总控保留指向该版本的记录。不同运行端不会自动同步本地文件，需要显式复制这份非敏感协议并核对版本。
3. B 独占实现代码及自己的单元测试；C 独占评测代码和参考答案；共享协议由 A 负责决策，B/C 只提出变更请求。
4. B/C 各使用自己的输出子目录。每次实验记录协议版本、实现版本/文件摘要、模型配置和输入集合标识。
5. 先在合成证据上检查接口。第一轮参考集可选少量原文明示任务，沿已获批数据与模型范围执行；患者正文、模型凭据不进入跨 session 交接文件。

评测侧可以向实现侧提供开发集错误与合成回归例子。独立测试答案不回流为 prompt 示例或调参材料。第一批 10–20 个题目实例用于开发与流程调试，最终论文测试范围另行确定。

## 按依赖安排这一周

- **第一次工作单元**：用户和 A 明确输入输出与比较方式。B 只读核对可复用接口；C 定义任务格式和计分规则。
- **第二、三次工作单元**：B 实现直接抽取；C 整理小型参考集、实现评分器，先用合成结果联调。
- **第四次工作单元**：C 跑评分并整理错误；用户和 A 亲自看代表例子，决定只增加哪个模块。
- **第五次工作单元**：B 实现该模块并复跑；C 汇总质量与成本；A 写一页汇报及演示步骤。

每次集中查看 A，阅读 B/C 的简短状态即可。状态统一为：完成了什么、证据在哪里、当前卡在哪里、下一步是什么。代码完成、实验完成和结论成立分开记录。

下次汇报最小材料：一页任务/方法图、一张真实对照表、两三个典型错误、一项希望师兄判断的取舍。

## 可复制的开场说明

### A：继续当前总控任务

> 本周目标是为下次向师兄汇报准备一个 EHR Harness 小型对照实验。请依据研究实施笔记第 8 节，和我先写一页任务卡，明确输入、输出、计分方式及第一轮比较变量。你负责协议版本、参考文献和研究解释，汇总原型与评测两个任务的结果。把我需要亲自判断的内容压缩成具体例子与一次一个的问题。

### B：原型实现任务

> 本任务负责 EHR Harness 第一周原型。先进入实际 EHR 项目并读取适用规则，只读核对现有标准试卷、模型契约、任务构建和响应接收入口。取得总控定稿协议后，在专用实验代码目录复用接口，实现同一模型直接抽取与一个可切换模块，保存配置和轨迹。只写归属本任务的代码与测试，评测协议和参考答案交给评测任务管理。模型与真实数据操作沿既有具体授权范围执行，患者正文和凭据不进入对话。交付可重跑入口、合成接口验证和四行状态摘要。

### C：评测与错误分析任务

> 本任务负责 EHR Harness 第一周评测。先读取实际 EHR 项目规则和总控协议，在专用评测目录定义任务实例、参考答案和评分格式。第一轮选原文明示、可直接核对的字段/时间/来源任务；参考答案需对照证据核验，模型输出只作候选。可以先用合成样例完成评分器联调。收到实现任务的输出后生成质量、成本和错误表，保留失败与无法回答记录。只修改归属本任务的评测文件，对实现代码提出反馈；独立测试答案不作为实现侧调参材料。交付评分入口、结果表、代表错误和四行状态摘要。
