# KDD 目标论文 Idea 提案（v1）

日期：2026-09-08。目标：KDD 风格的计算机会议论文；具体投稿周期和截止日期待核对，KDD 2026 的公开投稿周期已经结束。
状态：候选研究设计，不是已完成成果。下文的创新点必须经实验与最近邻原文核验后才能写成论文结论。

## 一句话定位

把真实纵向 EHR 的“文档、时间和证据”组织问题，提升为 Data Agent 的数据基础设施问题：Agent 不是直接从一堆 PDF 生成答案，而是在查询驱动下构建、检查和复用带事件身份与来源的临床事实。

## 暂定标题

**Event-Provenance Harness: Query-Conditioned Structuring for Verifiable Analytics over Real-World Longitudinal EHRs**

中文工作译名：**事件来源感知 Harness：面向真实纵向 EHR 可验证分析的查询驱动结构化**。

标题里保留 Harness，是为了接上当前 Agentic Data Systems 的研究语言；真正的技术对象是 `event identity + provenance + query-conditioned materialization + evaluator`，不能只靠标题词汇制造贡献。

## Motivation

**Motivation 1：真实纵向 EHR 的困难在事件关系，而不是把文字改成 JSON。** 医院 PDF 导出把同一临床事件分散在不同文档、页面和版式中；文档记录时间、采样时间和报告时间可能不同，同一指标的重复引用也可能与真正复测混在一起。通用 LLM 或简单键值抽取即使识别出正确的项目和值，也可能把值、时间和来源配错，合并掉本应保留的观测，或生成没有证据支持的事件。这样的输出不能直接用于可信的纵向分析。

**Motivation 2：现有 Agent 工作已经把注意力推向异构证据、长时程任务和可执行评测，但真实 PDF EHR 的事件身份与证据关系仍缺少统一的任务接口。** DataSpace 证明异构工作区和完整结果评测会暴露 Agent 的可靠性瓶颈；ClinLens 把患者时间范围和执行语义纳入评测；HealthFlow 组织 EHR 分析的计划、执行和反馈。我们的切入点应进一步下沉到：在 Agent 开始分析前，如何按查询物化可验证的临床事件，并把重复、冲突、不确定和来源支持显式留在数据结构里。

## 三项创新点

三点不是三个并列功能，而是一条依赖链：没有 1，2 无法知道物化的对象；没有 2，3 只能评估静态抽取；没有 3，1 和 2 无法证明在真实数据上的价值。

### 1. Temporal-Provenance Event Identity Layer

提出一个面向真实 PDF EHR 的事件级表示和关联机制。一个观测不再只是 `key: value`，而是包含：

- 事件身份与事件类型；
- 事件发生时间、文档时间及其角色；
- 项目、数值、单位和异常状态；
- 页码/bbox/evidence id 等来源链；
- 重复引用、真正重复观测、冲突值和未决关系；
- `unknown`、低置信度和需要复核等状态。

核心不是增加字段，而是用事件身份和关系约束区分“同一次事件被多份文档引用”与“同一指标在不同时间复测”，同时允许相同值的真实重复观测保留。首轮重复检验任务是这个机制的最小可测切片。

### 2. Query-Conditioned Event Materialization Protocol

不预先把全部 PDF 全量转成一个巨大病例表。给定一个分析任务，Harness 先判断需要哪些事件和证据，再按不确定性、时间冲突和来源缺口决定是否检索更多文档、展开更多页面或请求模型补充语义抽取。每一步都产生可回放的中间事件、证据引用和决定原因；无法确定时保留未决状态，而不是强行补全。

这把“AI-ready”定义为任务可检验的状态：对当前问题，系统能提供符合 schema 的事件、时间语义、来源和不确定性，而不是笼统宣称所有数据已经 AI-ready。它与 Agentic Context Cracking 的共同点是按查询逐步结构化；差异应落实到纵向 EHR 的事件身份、时间角色和证据关系，而不是只做通用文档缓存。

### 3. Execution-Grounded EHR Harness and Evaluator

建立一个执行锚定的真实 EHR 任务协议与评测器。每个任务指定允许使用的匿名病例证据、目标事件 schema、时间可见范围、输出格式和预算；评测器独立保存参考答案，按事件级别检查：

- 项目/数值/单位是否匹配；
- 事件时间是否绑定正确；
- 来源是否真正支持答案；
- 应保留的重复观测是否被合并；
- 错误合并、错误拆分、漏事件、额外生成和适当 `unknown`；
- token、调用次数、耗时和失败类型。

任务可用程序化扰动构造难度层：文档乱序、重复报告、同值复测、冲突时间、缺失时间和跨页证据。真实肺癌 PDF 负责检验现实分布；合成/扰动任务负责控制变量和可复现边界。隐私限制下，论文可公开任务 schema、评测代码和合成伴随集；真实数据部分的开放范围需另行确认。

## 实验主张与对照

### 最小可检验主张

在相同模型、相同合法证据和可比调用预算下，事件身份/来源层加上查询驱动的证据组织，能否降低真实纵向 EHR 中的值—时间—来源错配，同时保留真正的重复观测？

### 最低对照

1. 规则/现有解析器：记录确定性工程基线，不把它包装成强模型基线。
2. 同一模型直接抽取：给定共同证据和固定输出 schema。
3. 同一模型 + Event-Provenance Harness：增加事件身份、时间角色和证据关系组织。
4. 消融：去掉时间关系、去掉来源检查、改为静态全量结构化；报告质量—成本曲线。

固定模型、输入证据、上下文策略、输出 schema、重试上限和预算。独立测试按病例划分，参考答案不进入模型输入或提示示例。

## 证据路线

### 首轮实验

重复检验的项目、值、单位、时间和来源配对。先从原文明示、可直接核对的字段开始；临床推断暂不作为主要任务。工程侧已有时间候选适配器 v0.3.1 的合成测试和两例开发样本验证，但日期角色和检验行绑定仍待完成。

### 第二轮

加入重复报告与真正复测的区分，测试事件身份层：同一事件多文档引用、同一项目不同时间复测、相同值不同时间、冲突来源和不确定时间。

### 第三轮

测试查询驱动物化：改变问题需要的事件集合，测量结构化覆盖率、额外调用、证据支持和跨任务复用成本。

### 第四轮

在独立病例集上进行主实验、消融和难度分层；按文档长度、重复程度、时间歧义和 OCR 质量报告边界。

“四轮”是研究目的的安排，不是固定运行次数。每一轮都可能发现假设不成立并回退设计。

## 反驳审查

**反驳 1：这只是 ETL、RAG 或常规事件抽取。** 如果方法只按日期排序、分块、调用一次模型，就不能称为非增量创新。必须展示事件身份关系、查询触发的物化决策和可验证 evaluator 如何共同改变结果。

**反驳 2：提升来自更多调用或更干净的时间输入。** 对照必须固定预算并报告 token、调用次数和耗时；两组共享同一合法时间适配。必要时增加预算匹配和去掉时间模块的消融。

**反驳 3：大规模真实数据本身不等于贡献。** 数万病例只能支持规模、分布和稳健性分析；准确率仍依赖独立核对的任务集。文件总数不能替代病例数，开发样本不能替代测试集。

**反驳 4：DataSpace、ClinLens 或最新临床 Agent 工作已经覆盖了这个问题。** 相关工作必须逐篇核对事件身份、时间角色、来源 bbox、重复观测和查询驱动物化是否真的存在。当前仅凭摘要不能排除重合。

## KDD 适配判断

KDD 方向更适合强调数据与系统机制、可验证任务和规模化实证，而不是把论文写成临床工作流报告。该提案的主贡献候选应落在“事件级数据 substrate + 查询驱动 Harness + 执行锚定评测”这一组合上；肺癌是高价值真实数据场景和压力测试来源，不把临床效果或医生认可写成主结论。

1. 您希望主贡献更偏事件级数据表示、查询驱动 Harness，还是评测协议？三者可以成链，但需要确定论文主轴。
2. 您上次提到的多时序、模型层和 protocol，是否对应这条事件身份—查询物化—执行评测链？如果不是，最接近的论文或方法图是哪一个？
