## 题目

**Event-Provenance Harness: Query-Conditioned Structuring for Verifiable Analytics over Real-World Longitudinal EHRs**

## 中心命题

**值抽对了，事件数不对。** 在真实 OCR 医院 PDF 上，一个 Data Agent 可以把每个检验数值都抽对，却分不清哪些记录是同一次采样的副本、哪些是真实独立复测，从而把"测了 3 次"报成"5 次"。这类错误不体现在任何值级指标上，却直接污染纵向分析：复测间隔、趋势斜率、跨机构报告计数。

因此我们研究一个**嵌套 Harness**：外层在跨文档视野下判定检验事件身份并做预算路由，内层在文档内重建表格结构、绑定项目/值/单位并归一四类时间角色（采样/报告/记录/文档）。二者互为条件——外层决定内层看到什么，内层提供外层判身份所需的标本/报告号证据。

## Motivation

1. 真实医院数据中同一次检验被多次记录极为普遍：ACIE 报告对真实数据做内容级去重时，中位去掉 33.5% 的文档、最高 54.6%。现有系统只做**文档级字符串去重**，会把"同一次采样的多份报告"当成副本合并，也会把"真实复测"合并成一次。
2. 临床化学一侧已经解决了相邻的一半问题：CCLM 2025（PMID 40991454）为多实验室累积检验报告提出 LOINC/UCUM 可比性分组与"保留测量来源"的规范，其动机原文即"让医生跟随真实患者趋势，而不与实验室引入的变异混淆"。**该规范处理的是"同一分析物跨实验室"（测量可比性），没有处理"同一次采样被多条记录重复计数"（事件身份）。**
3. 值级准确率无法暴露这一错误。ACIE 的医生核验给出按字段类型的接受率：categorical/boolean 98.6%、numerical 98.3%、free text 96.0%、**date 84.3%、tabular 79.8%**，且 **hallucinated reference 为 0.0%**——"来源支持"已不是主要错误源，而时间与表格结构仍是最弱项。

## 贡献（按证据分级）

1. **主贡献｜事件身份的联合判定**：在检验事件这一对象上，联合（a）文档级近重复信号与（b）文档内抽取到的标本/申请/报告号证据，把同一患者同一项目的多次出现判为 {同一次事件的文档副本 / 同一次采样的多份报告 / 真实独立复测}，产出可计数、带 provenance 的检验事件，并报告误合并率与误拆分率。
2. **机制｜嵌套 Harness**：外层（跨文档身份判定 + 预算路由）与内层（文档内结构重建、值—项目绑定、四类时间角色归一）互为输入。单层平铺在信息上无法同时使用两类身份信号——这是"嵌套"的必要性来源，不是设计偏好。
3. **评测｜解耦报告**：值级准确率与事件级准确率分开报告，并测身份错误对下游（复测间隔、趋势斜率、跨机构计数）的代价。

### 新颖性表述的边界（必须守住）

**不得声称"首次提出事件身份判定"。** 以下均已成熟，动笔前必须读并引用：

| 相邻工作 | 做到了什么 | 与本工作的关系 |
| --- | --- | --- |
| Son & Taira 2004（PMID 15361043） | 跨文档判定多次 CT 报告中的肺肿块是否同一发现；P=72% / R=63% | **任务形状相同的先例**，对象是影像发现而非检验事件 |
| THYME 跨文档共指标注规范 | 同一患者跨笔记的临床事件共指标注 | 提供任务合法性，不含副本/复测区分 |
| Gabriel 2018（PMID 29679685） | MinHash/LSH 文档级近重复检测，1,528,940 条笔记，JS≥0.7 得 82,371 簇 | **现成的文档级信号**，本工作直接复用，不重新发明 |
| SemEval-2016 Task 12 narrative containment | 跨文档叙述包含（副本）检测 | 文档级，无事件身份 |
| CCLM 2025（PMID 40991454） | 多实验室检验报告的可比性分组与来源保留 | **互补**：它解可比性，我们解事件计数 |
| IIS 剂量级去重 / vigiMatch（药物警戒）/ UMI-tools（测序） | 其它领域的事件级去重与来源标识判定 | 证明方法现成；**不能把"提出事件身份判定"当创新** |

**我们的位置**：检验事件 + OCR 抽取层这个具体对象上的**联合判定**与**首次测量**。两类信号单独都不够——文档级信号分不出"同一次采样的两份报告"与"两次真实复测"；标本号在 OCR 文本里常常缺失，只能在不完全信息下判定。

## 我们的数据优势与边界

现有 inventory 记录约 39,560 个病例目录和 462,789 份 PDF；这首先是目录/文件规模，不能直接写成独立患者数或科研可用样本数。与常见 KDD/医疗 Agent 工作相比，真正有区分度的优势是：

- 原始医院 PDF 的文档级异构性、跨页版式和 OCR/bbox 证据，而不是已经整理好的 MIMIC 表或 FHIR 虚拟 EHR；
- 同一病例多文档、多时间点、重复报告与真实复测共存，可观察事件身份和时间角色错误；
- 能以真实数据分布做压力测试，再用合成扰动构造可控评价；
- 规模足以报告不同文档长度、重复程度、时间歧义和 OCR 质量下的质量—成本曲线。

常见对照数据源包括：公开去标识结构化 EHR（MIMIC、EHRSHOT、UK Biobank）、FHIR/模拟 EHR（MedAgentBench）、合成或渲染 benchmark（DataSpace、FDABench），以及少量真实医院/多中心数据。HealthFlow 已用公开 MIMIC-IV Demo 和 485 例 COVID 时序数据建立 100 项 EHR 分析任务；ClinLens、ClinTraceBench 和 EHR-Complex 也已覆盖纵向任务、来源或执行评测。因此“真实、规模大、用了多 Agent”都不能单独作为创新。

KDD 卖点应写成“真实 PDF EHR 文档分布 + 事件级任务协议 + 可控执行评测”，并公开不含患者内容的 schema、评测器、合成伴随集和匿名聚合统计。需要向师兄/数据负责人确认的真实数据统计包括独立患者数、文档数、事件数、时间跨度、重复率和可用于评价的病例数。

## 首轮实验（E1，2026-11 中旬交付）

在 2–5 份真实检验文档上，用**真实模型**跑三行对照，报告三组指标：

| 条件 | 外层（跨文档身份判定） | 内层（文档内绑定） |
| --- | --- | --- |
| Flat | 无 | 无（一次性全量输入） |
| 单层 Harness | 无 | 有 |
| **嵌套 Harness** | 有 | 有 |

指标：值级准确率、误合并率、误拆分率。

**核心证据形态**：若三行的值级准确率接近，而事件级指标只有"嵌套 Harness"一行正确——该表即为论文的主证据，也是"嵌套必要性"的直接论证。

**闸门（不成立则改任务定义或数据切片）**：
1. 真实数据中是否存在"同一次检验被多次记录"的现象（含报告号/条码号等身份证据）；
2. 误合并/误拆分率是否高到足以支撑论证。若极低，改用"低频但高后果"论证，并须由实测数据支撑，不得靠论述。

真实模型效果尚未产生。

## 现有基础与缺口

- 时间候选适配器 v0.3.1 已完成局部工程验证。B 新增显式角色/行关联校验草案，尚需实际证据角色识别与表头作用域；最新状态见 [实现记录](../status/implementation.md)。
- 事件身份归并、查询驱动物化、评分器、独立参考集、真实 A/B 和消融实验尚未完成。

## 必须证明的三件事

1. 事件身份机制确实区别于普通 ETL/RAG/去重，而不是换名或增加字段。
2. 在相同模型、证据和可比预算下，机制能减少关系错误，并且收益不只是更多调用带来的。
3. 独立评测能够判断来源是否支持正确事件，而不是只检查引用格式。

如果这些证据没有出现，主张应降为单中心纵向 EHR 开发切片上的受控事件匹配实验，不能宣称通用 AI-ready substrate 或 KDD 级 benchmark。
