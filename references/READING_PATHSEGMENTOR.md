## 一、为什么这篇值得抄（不是抄内容，是抄结构）

它和我们的处境高度相似：**数据分散、口径混乱、没有统一定义**。它的处理办法不是发明新模型，而是
**先把 21 个公开数据集对齐成一套统一的层级标签空间（PathSeg）**，然后在上面训模型。
作者自己在"怎么看这篇论文"里也承认：**最有长期价值的部分可能不是模型，而是 PathSeg 这套整理工作。**

→ 这直接支撑我们的定位：**"把数据整理成 AI 能直接用的样子"本身就可以是主贡献。**

## 二、图的设计要点（可迁移的三条）

### 1. 一张"总览图"把"我们的数据集又大又有结构"说清楚（图 1）

`pathsegmentor_figs/pathseg.png` 四个面板：

| 面板 | 画的是什么 | 我们的对应 |
| --- | --- | --- |
| a | 21 个数据集拼成 treemap，面积=掩膜数；蓝=内部、红=外部验证 | 我们的语料：病例 → 文档类型 treemap（面积=文档数） |
| b | 横向条形对比其它数据集（**对数轴**）：275k vs 15k / 9k / 1k | 对比已有 EHR benchmark：病例数 / 表数 / 字段数 |
| c | **桑基图**：20 解剖部位 × 3 组织层级 × 61 对象 → 160 类 | 患者 → 就诊 → 文档类型 → 16 张事件表 → 字段 |
| d | 三个饼图：按部位 / 层级 / 对象类型的占比 | 按表 / 按字段 / 按"有没有时间"的占比 |

**要点**：一张图同时回答"多大、多有结构、覆盖在哪"。**这是审稿人第一眼看的东西。**

### 2. 不报单一平均数，而是画"随难度变化的曲线"（图 6）

`pathsegmentor_figs/performance_spatial_complex_0625_compressed.png`：

- a：Dice 随**形状不规则度**变化（规则 → 不规则），散点 + 拟合曲线 + 置信带
- c：Dice 随**实例尺寸**变化（大 → 小）
- f：Dice 随**实例密度**变化（低 → 高）
- **g：Dice 随"每个掩膜需要几个提示"变化** ← 质量—成本权衡图
- b/d/h：定性例子，每张标 Dice
- e：分布直方图（说明测试集的难度构成）

**要点**：难度轴是**定量定义的**（不规则度 = 1 − 圆度；实例尺寸比；实例数），不是主观分层。
**我们的对应**：难度轴 = 病例行数 / 文档数 / 表格类型 / 模板；纵轴 = 一次性完成率；
成本轴 = 每病例调用次数、token、人工介入次数。

### 3. 诚实地把"对手在什么条件下赢"画出来（图 6g）

他们主动披露：**给 MedSAM 每个实例单独画框，Dice 反而更高（0.77~0.79 > 0.671）**，
代价是每个掩膜平均要约 15 个提示。这一格让整篇论文的可信度大幅提升。

**我们的对应**：主动披露"多跑几次 / 加预算之后，单次调用系统的完成率也能上去，代价是 X 倍成本"。

## 三、边界：不能照搬的地方

- **它是视觉分割，我们没有图像模型贡献**。我们只有数据 + 评测，所以定位应该落在
  KDD ADS / NeurIPS D&B 这类认数据集与系统评估的口子，而不是 KDD Research Track。
- **封闭词表**：模型只认训练见过的 160 类；"自然语言"实际是 LLM 把自由文本改写成固定模板；
  **没有测零样本能力**。这是它的短板，也是审稿人会打的点——我们不要重复这个坑。
- **可解释性未经病理医生盲评**，只跟文献标准对照。→ 提醒我们：**没有医生评估就要主动声明**。
- **它是预印本**，不能当"已被接受"的模板。

## 四、"AI-Ready" 这个词的先行工作（重要，影响定位）

师兄要求"瞄准 AI-Ready 来打"。查了一下，**这个词在临床数据领域已经被用过，但都不深**：

| 来源 | 它怎么用这个词 | 和我们的差别 |
| --- | --- | --- |
| [From Medical Records to AI-Ready Datasets: A Practical Guide for Clinical Researchers](https://www.mdpi.com/2077-0383/15/16/6297)（J Clin Med 2026） | 提了一个 **0–2 三级序数**的"数据集就绪度"量表，靠**人工评估** | 我们不是打分，是**把库丢给一个没用过的 AI 直接问**，看它能不能用 |
| [MedRxiv: Multi-Agent clinical pre-consultation → AI-ready data](https://www.medrxiv.org/content/10.64898/2026.06.10.26355372v2.full) | 把患者自述结构化成"AI-ready data"，然后做下游效用对照 | 它是单一系统；我们是**同一条流水线的 5 个就绪度版本做消融** |
| Snowflake / Data4Life 等工业框架 | 工程口径的"AI-Ready Data Framework" | 非学术，但**说明这个词在业界有共识、好用** |

（MDPI 那篇正文被 403 挡住，只拿到摘要片段："The three-level 0–2 scale was selected as a deliberately
simple ordinal representation of dataset readiness"——**是人工量表**，不是可执行指标。）

**→ 定位机会**：现有工作把 "AI-Ready" 当成**人工打的等级**或**一次性对照**，
**没有人把它定义成一个可由外部 Agent 复现的可证伪指标**。
我们要做的正是那一格：**"就绪度 = 一个没参与建库的 AI，在无说明书、无示例、无人工干预下，
能直接答对多少问题、费多大劲、错在哪里。"**

**同时要小心**：这个词有先行工作，**必须引用**；不能写成我们首创。
