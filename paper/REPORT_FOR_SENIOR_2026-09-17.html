02三条结论

结论 1：引用可解析率已经废了

三个模型设置、3942 行，引用可解析率全部 100%。现有临床抽取评测报的就是这个指标 （ACIE 报 hallucinated reference 0.0%）。它已经饱和，分不出系统好坏。

结论 2：能分开系统的是时间落地

同一个模型、同一个输出上限、同一批文档，只换了上下文范围：整病例一次问时间接地 58.6%，同类合并和逐文档都是 100%。

03行数真值是怎么算的

不用人工数。每页把格子的横坐标做直方图，连续密集的一串算一列；值列就是那一列里 六成以上是纯数字、且位置在页面中右部（这样最左边的"序号列"不会被误选）。然后按纵坐标把值格聚成行， 聚出多少簇就是多少行。

12 个病例算下来 2518 行。跟模型对照：CASE-05 几何 139 / 模型 141；CASE-06 几何 330 / 模型 315； CASE-09 几何 293 / 模型 291。没找到值列的 75 页平均只有 50 个格子、其中纯数字占 4%，是纯文字页，不是漏行。

要说明的是：这不是医生金标准，是"文档结构上确实有多少行"。它可以逐页复算，但没有人逐行核对过。

04请师兄定四件事

① 主表的行列就按上面这样定，行不行？
行的顺序：规则 → 整病例 → 同类合并 → 逐文档。列就是那九列。

② "值接地"用哪个口径？
问题：同一份输入重跑三遍，值接地是 95% / 95% / 84%，跳 11 个点。引用和时间都是 100%/100%/100%，纹丝不动。
原因：文档写 5.60，模型抄成 5.6 判接地，抄成 5.60 也判接地；但文档写 5.6、模型写 5.60 就判不接地。小数位写法一变，百分比就跳。
三个选项：报区间（"84%，三次 95/95/84"）／跑多次取平均（成本翻 3~5 倍）／换成"数值相等"口径（98.9~99.8%，三遍基本不跳，但抓不到格式差异了）。

③ "系统级失败"要不要单列一列？
具体例子：CASE-100 的文档里实实在在写着 514 行检验结果。整病例一次问时模型要一次吐出 514 行 JSON， 输出上限装不下，返回断掉的 JSON → 这个病例最后是 0 行。它把这行整体拉低约 20 个点。
但："抽了 50 行、漏了 464 行" 是抽取能力问题；"一个字都没吐出来" 是系统跑不完。 混在一列，看表的人会以为系统抽得不全，其实是根本没跑出来。把上限提到 64000 后，CASE-02 从 0 行变 286 行（真值 290）、 CASE-09 从 0 行变 291 行（真值 293）——一恢复就是 98% 的准头，说明它本来抽得出来。
建议：拆成"跑通病例数 / 总数"和"跑通病例上的行数恢复率"两列。

④ 拿几何真值当"行数恢复率"的分母，行不行？
它不是医生金标准。要不要只当辅助列，主指标换成别的？
