02结论：三种问法分不出来，真正的问题是跑不出来

修掉两处缺陷之后（第 04 节）：引用 100%、时间 100%、值 99~100%，三种问法都一样。

唯一稳定的差别是"有些病例系统根本跑不出来"：

系统跑不出来的病例表现
规则/几何0——
整病例一次问3 / 12CASE-02、CASE-06、CASE-100
同类文档合并4 / 12CASE-02、CASE-06、CASE-09、CASE-100
逐文档分开问3 / 12CASE-02、CASE-04、CASE-100

失败的表现是返回的 JSON 被截断、解析不了，不是"抽得少"。 CASE-100 的文档里实实在在写着 514 行检验结果，一次调用根本吐不完。 把输出上限从 16000 提到 64000 后重跑，CASE-02 从 0 行恢复到 286 行（真值 290）、 CASE-09 从 0 行恢复到 291 行（真值 293）——一恢复就是 98% 的准头。

这一格必须和"抽得少"分开看： 把跑不出来的病例算成 0 分，行数恢复是 40~48%；只算跑通的，是 76~93%。 两种算法差一倍，混在一起会得出完全相反的结论。

而且失败的病例每次跑不一样。同样配置再跑一次， CASE-04 从"正常 147 行"变成"跑不出来"，CASE-09 从"291 行"变成"10 行"。 所以"跑通病例数"这一格本身也有噪声。

03行数真值（还没修好的一格，不敢用）

做法是几何的：每页把格子横坐标做直方图，连续密集的一串算一列；值列是那一列里 六成以上是纯数字、且位置在页面中右部（这样最左边的"序号列"不会被误选）。 再按纵坐标把值格聚成行，聚出多少簇就是多少行。12 病例得 2518 行。

04指标口径

值接地：以「数值相等」为主口径

判定规则是去掉尾零、千分位、前导零之后比较。
主口径下 99~100%；逐字口径下 82~88%，差的 12~14 个点全部是尾零/千分位/前导零， 且全部出现在模型自己引用的那份文档里——这是格式差异，不是编造，所以逐字口径只作脚注。

时间接地：time_refs 允许指向多行

报出的时间必须逐字出现在它引用的 time_refs 行里。
实测依据：538 个时间对不上的行里，302 行所在的文档中没有任何一行同时含日期和时刻。 所以 time_refs 必须允许指向多行（日期一行、时刻一行）—— 和 source_refs 是「证据集合」同一类设计。

引用可解析率作第一道闸

引用的行号必须真实存在。这一闸不过，其余指标全部无效（输出被截断时最先失效）。

05请师兄定的事

① 主表现在是这样，行不行？
行：规则 → 整病例 → 同类合并 → 逐文档。列：引用可解析 / 值接地（逐字+归一化）/ 时间接地 / 跑通病例数 / 行数恢复 / 成本。另外把"跑不出来"单列了一列。

② 现在三种问法分不出来，这个方向还能不能做？
主表现在的信息量基本只有一条：好的契约下，前沿模型的抽取是可追溯的； 真正的失败是工程性的（大病例吐不完），不是能力性的。
这算不算一个能讲的结果？还是说要换角度（比如把规模铺到 200 病例、把 16 张表全做、换更难的题）？

③ "行数恢复率"要不要现在就报？
几何真值还没校准（CASE-01 出现 122%）。我倾向于先校准、暂时不报，或者只报"跑通/跑不出来"。

④ 要不要为了"能分开系统"去加难度？
现在分不出来，可能是因为任务对前沿模型太简单。可选：换成用药表/诊断表（时间在行内，更难）、 加大病例规模、或者用更难的问法。想听你的判断。

06还没做的（不遮掩）

  • 16 张事件表只做了 1 张。检验表是唯一有稳定网格结构的；用药表、诊断表的时间在行内不在页脚。
  • 规模只有 12 个病例（池子里有 200 个）。
  • 只测了一个模型（最便宜的那个）。
  • 几何真值没校准，所以"行数恢复"这一列还不能用。
  • 为什么大病例跑不出来知道是输出预算，但为什么每次失败的病例不一样没查。
  • 内容正确率做不了（没有医生金标准）。本表所有格子都是机械可算的"可验证性"，不是"答得对不对"。
