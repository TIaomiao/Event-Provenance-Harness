# AI-Ready 医疗数据库：方向与实验协议

本文件是"AI-Ready 医疗数据库"这一方向的**常驻说明**：方向、五个版本的定义、五个指标的定义、实验协议、已有证据与边界。总控面板 [CONTROL_PANEL.md](../CONTROL_PANEL.md) 与本文件分工：面板给当前状态，本文件给定义与协议。

方向来源：师兄 2026-09-17 的口头指令——"做一篇 AI-ready 的医疗数据库论文，主要用 Agent 来提取复杂的医疗数据"；把数据库做成"洗好切好贴标签的菜"，证明方式是**交给一个没参与建库的 AI，不给指令、不给例子、不许人帮忙**，看它能不能直接用。数据集自己造，答案是"格级/文档级"的。

2026-09-18 的归属（逐条写清，避免以后再混）：

| 真实原生数据更有参考价值与难度；**纵向序列需要对时间应对**；**后续加点影像** | **契阔**（17:36–17:37 原话） |

## 一、一句话方向

**把真实医院扫描 PDF 变成"现成 AI 能直接用"的数据库，并逐层量出每个准备动作各值多少。**

测量对象不是"我们的抽取器准不准"，而是**同一批问题、同一个没参与建库的 AI，换不同的数据版本，做对率 / 成本 / 错答结构 / 可核对性怎么变**。

与 FHIRBench 型工作的分工：它比"**已经结构化的数据**怎么序列化"，我们比"**扫描件 → 能用的数据**"这一段——版面污染、印章、定性结果、页码误入、单位印刷形全在这一段里。

## 二、五个版本：超集阶梯

每个版本都是前一个版本的**严格超集**：原文一行不删，逐层加一样东西。这样任何两个版本之间的差异只能归因于那一层。

| 版本 | 加的东西 | 具体是什么 |
| --- | --- | --- |
| **v1 生数据** | —— | OCR 原文行，按病例/文档/行号导出 |
| **v2 格式统一** | 统一信封 | 每份文档一条固定字段的头对象（病例、文档号、类别、页数、行数、采集日期），每行带页码与格子坐标；任何文档类别读法一致 |
| **v3 单位归一** | 观测表 | 检验文档追加 `[obs]` 观测行：项目名、缩写、数值、规范单位、参考区间、上/下限、数值标记（偏高/偏低/文本/未知） |
| **v4 溯源与状态** | 证据与状态 | 每条观测带来源（文档号/页/格子 bbox）；每份文档带抽取状态（行数、页数、OCR 状态、观测数） |
| **v5 机器说明书** | 说明书 | 前导的机器可读说明：字段含义、单位规范形与印刷形对照、状态码取值、计数规则 |

**反向拆件**：从 v5 各去掉一层，得到 v5−说明书、v5−溯源与状态、v5−单位归一、v5−格式统一。去掉说明书时按构造等于 v4，所以反向条件实际多出 3 个点。正向 5 点 + 反向 3 点 = **8 个条件**，同一批问题、同一个消费者模型各跑一遍。

## 三、五个指标

| 指标 | 定义 | 怎么量 |
| --- | --- | --- |
| **做对率** | 按题型分别报（"算一下"/"查一下"/"真没有"） | 与机械答案键比对；数值题按 0.5% 容差，计数题按整数相等 |
| **费劲程度** | 输入 token、输出 token、单次延迟、单次成本 | 从网关 usage 字段读取；逐条件汇总 |
| **错答率（含错否定）** | 给出肯定性回答但答错的比例；"真没有"型单独统计**错否定**（对象存在却答"没有"）与**错肯定**（对象不存在却答"有"） | 对"真没有"型答案做语义归一（有/无/拒答三类），分别计数 |
| **该说不知道时说了没有** | "真没有"型题的拒答率与正确拒答率 | 拒答关键词表 + 与键的联合判定 |
| **医生核对时间** | **代理指标**：引用可解析率 + 从引用走到原始格子的步数 | 答案里的 source 是否指向存在的文档/行/页；3 级=文档+定位、2 级=只有文档、1 级=只有行号、0 级=无法核对 |

**最后一项必须写成代理指标**：不引入医生就无法测真实的核对时间。可测的是"读者能不能顺着答案走回原文"，这是核对时间的上界代理。

## 四、实验协议

**数据范围**：一个全量批次 `batch-full-01`，**984 个病例 / 5,255 份文档**（第一轮扫描 400 例得到 13.1 份文档/例）。真实医院 PDF 与 OCR 产物，不复制到本地。

**两族问题，同一批次**：

| 族 | 规模 | 用途 |
| --- | --- | --- |
| **病例级** | 12 例 × 6 题 | 五版本阶梯的正向曲线与反向拆件；原文能装进上下文，五个版本都可跑 |
| **队列级** | 整批 984 例 × 10 题 | 跨病例聚合；原文装不下（上限约 10 例），只有结构化各层能跑，用来看"规模上还剩哪些层有用" |

**病例级六题**（一例一次调用，问全部六题；算一下 4 题 / 查一下 1 题 / 真没有 1 题）：

| 题 | 型 | 问什么 | 答案键 |
| --- | --- | --- | --- |
| Q1 | 算 | 白细胞（WBC）最大测量值（含单位） | 几何层同项最大行 |
| Q2 | 算 | 血红蛋白（HGB）最小测量值（含单位） | 几何层同项最小行 |
| Q3 | 算 | 高于自身参考区间上限的结果行数 | 几何层逐行比较 |
| Q4 | 算 | 低于自身参考区间下限的结果行数 | 同上 |
| Q5 | 查 | 检验报告文档份数 | 文档类别计数 |
| Q6 | 真没有 | 文档里是否出现过某关键词 | 全文关键词计数；样本内一半病例的键为"有"、一半为"无" |

**答案键的来源与校验**：键由**几何层**产出，**零模型参与**（所以不存在"出键模型=被测模型"的循环论证）。几何层读印刷表头，按列心把格子绑到列上，按行距聚类成行。校验方式是与一条**不依赖行聚类**的独立口径比对——数"结果列里能解析成数字的格子数"：全批 130 份检验文档上两口径一致率 **85.3%**；逐项 recall（几何层抽到的行 / 印刷缩写格数）WBC 87.8%、HGB 98.8%、CREA 91.1%、PLT 98.8%、UREA 90.1%。差额主要来自**按单位正确排除**的体液标本（如尿白细胞按 /HP 计），以及印刷表头缺失的页。**该 recall 是本轮答案键的误差上界**，逐项写在结果文件里。

**消费者与约束**：消费者模型与建库过程无关（本轮建库为纯机械脚本）；**一次调用、不给例子、不给提示、无重试、无人工干预**；温度 0；模型名逐轮记录（网关可用型号每小时漂移）。

**评分口径**：引用可解析率作第一道闸；数值题以数值比对为准，单位正确性单列；"真没有"型把"否/没有/未提及/未找到"计为否定回答，把"无法确定"单列为拒答。

## 五、已有证据（截至 2026-09-18）

| 实验 | 规模 | 结果 | 文件 |
| --- | --- | --- | --- |
| 主表（三种问法 × 12 病例） | 12 例 | 引用 100%、时间接地 100%、值归一化 99~100%；**一次性完成率 50~58%** | [results/2026-09-17_main_table.md](../results/2026-09-17_main_table.md) |
| 试跑（60 题 × 三版本） | 12 例 | 原文 67% / 结构化替换 58% / 超集 65%；**收益只在成本（5.5 倍）** | [results/2026-09-17_pilot_ai_ready.md](../results/2026-09-17_pilot_ai_ready.md) |
| 难题集（双模型独立出键） | 12 例 50 题 | 原文 100%、结构化 78%、库+原文 84% | [results/2026-09-17_hard_questions.md](../results/2026-09-17_hard_questions.md) |
| 队列级 | 10~984 例 | **原文硬上限 10 例**（12 例超 1,048,576 token）；结构化一次装下整批 984 例 | [results/2026-09-18_queue_level.md](../results/2026-09-18_queue_level.md) |

**三条已经站得住的结论**：① 结构化层在**准确率**上没有增益；② 有损地替换原文明确更差，**AI-Ready 层必须是附加的**；③ 单病例上它的收益是成本，**队列级上它是"能不能做"**。

## 六、边界（必须与结论一起出现）

- **无医生金标准**：内容正确率测不了；"临床等价匹配"做不了。
- **单人核对答案键**：报不出标注者间一致性（κ）。
- 几何层答案键有 88~99% 的逐项 recall（见上），因此绝对做对率有不确定度；**跨版本比较不受影响**（所有条件共用同一答案键）。
- 目前只测 1 个消费者模型；文档类别里只有检验类文档有机械可算的答案键。
- 网关型号供应有小幅漂移，模型名逐轮记录。
- **必须引用且不得越界主张的两篇**：FHIRBench（medRxiv 2026-07-14.26358020，合成 FHIR bundle 上的序列化比较）与 HoloBench（arXiv 2410.11996，长上下文聚合退化与 max/min 抗退化）。任何一句"没人做过格式/上下文对可用性的影响"都会被这两篇直接否掉。

## 六之二、第六层：纵向时间轴 v6 = v5 + 时间轴（**已定案**）

**背景**：师兄在 2026-09-08 就提过"多时序"，当时作为问题挂在 [paper/KDD_IDEA_REVIEWED_2026-09-08.md](KDD_IDEA_REVIEWED_2026-09-08.md) 与 [RESEARCH_CARD.md](../RESEARCH_CARD.md) 里（"您上次说的'多时序、模型层、protocol'具体对应什么机制？"）；契阔 2026-09-18 又明确要求"medical 的纵向序列需要对时间应对"。**v6 就是把这条挂了十天的线落地成阶梯里的一层。**

**v6 比 v5 多出来的材料**（全部是"时间已经算好"的，不是让模型自己去读日期）：

| 位置 | 字段 | 含义 |
| --- | --- | --- |
| 文档头 | `date_role` | 采集 / 报告 / 未知——由印刷标签判定 |
| 文档头 | `day_index` | 相对该病例**首次检验采集日**的天数（0 为首次，可为负，取不到日期为 null） |
| `[obs]` 行 | `date` / `day_index` | 该行所在文档的采集日期与其天数序号 |
| `[timeline]` | 每天一条 | `{date, day_index, documents, observations, above, below, text_results, items}`——当天有几条观测、几条超上限、几条低于下限、做过哪些项目 |
| `[timeline_summary]` | 每病例一条 | 首末采集日期、跨度天数、有检验的天数、检验文档数、**检验与医嘱同日的天数**、无日期文档数 |

**实验位置**：阶梯变 6 层（v1 → v6），反向多一个点 **v6−时间轴**（按构造等于 v5，因此病例级反向点从 3 个变 4 个）。队列级同一套：结构化链加 **d6**，反向加 `mt`。

**共同前置：日期抽取校验**（脚本 `date_audit.py`）。目前每份文档从带"采集/检验/报告日期"标签的行取日期，取不到才退回文档首个日期；校验方式与行计数同法——两个不同家族的强模型独立列出每份检验报告的采集日期，与几何层逐份比对，一致率与覆盖率写进结果文件。

**时间题（键仍机械可算，已并入题库 Q7~Q9）**

| 题 | 型 | 问什么 | 答案键 |
| --- | --- | --- | --- |
| Q7 | 查 | 该病例最早的检验报告采集日期 | 检验文档日期最小值 |
| Q8 | 算 | 血红蛋白最小值出现在哪一天 | 同项最小行的文档日期 |
| Q9 | 算 | 该病例有几天的检验报告与医嘱执行记录同日 | 两类文档日期交集大小 |
| A11~A13 | 算 | 队列级：首末间隔 >30 天的例数 / 有检验的天数合计 / 有同日的例数 | 逐例机械计数（**只有 d6 答得出**） |

**边界**：日期题一律先报"可计算键的覆盖率"（题库生成时已自动打印逐题覆盖数）；覆盖率低的题要么缩小样本、要么降级成"该说不知道"型的配额。缺日期的观测写 `date: null` 并计入 `observations_without_date`，不猜。

## 六之三、自动研究（autoresearch）接入：把协议做成 agent 能自动跑的形态（**已定案**）

形态定为"**实验协议本身可被 agent 无人值守地跑完**"，不是"让 agent 拿库自由做研究"。已经落地的三件事：

| 能力 | 实现 | 状态 |
| --- | --- | --- |
| **一条命令跑完全部** | `driver.py`：9 步（扫描建库 → 出题 → 渲染载荷 → 病例级 9 条件 → 键定稿 → 重打分 → 队列级正向+反向 → 日期校验 → 汇总） | 已写好 |
| **可中断可续跑** | 每一步先查产物存在与否，存在就跳过；断线重跑同一条命令即可 | 已写好 |
| **自动出题** | `qbank.py` 从机械事实直接生成 11 道题与答案键（含时间题与影像题），并打印每题键覆盖率 | 已写好 |
| **自检** | driver 结束时逐项核对：9 个条件是否都在、每次调用是否 HTTP 200、5 个产物是否齐全；缺什么直接打印 MISSING | 已写好 |
| **可直接发布的汇总** | driver 产出 `PUBLISH.json`（只有聚合数字：各条件做对率/成本/来源等级、键审计、日期审计、逐题通过数），脱敏后可直接进 `results/` 与看板 | 已写好 |

**它现在是"agent 能跑"，还不是"agent 会自己想"**：题目模板、条件集合、阈值都写死在脚本里。下一层能力（agent 自动提新题、自动判定某个结果是否值得复跑、自动写结果文件）还没有实现，需要时再往上加。

### 题的临床化：分层题集（与自动跑不冲突）

临床化的题（"有多少例的某项指标在治疗开始后跨过阈值"）必须引入临床定义——治疗起点、观察窗、跨阈值判定——**这些定义无法纯机械导出**，键就不再是"零模型"的。处理方式是分层，两部分互不污染：

| 层 | 题 | 键来源 | 在论文里的位置 |
| --- | --- | --- | --- |
| **L1 机械题集** | 队列级 A0~A15 + 病例级 Q1~Q11 | 几何层/文档级机械计算，**零模型** | **主结果**：六版本曲线、反向拆件、成本与可核对性 |
| **L2 临床题集** | 3~5 题（治疗起点后跨阈值、随访间隔、跨文档事件对齐等） | 强模型出候选 + 人工核（按已定的三层答案键协议 L1 机械 / L2 模型 / L3 人工） | **辅助结果**：证明"库能被用来做真分析"，并标注键的来源与不确定度 |

这样自动跑的主链路（driver）始终只跑 L1；L2 作为单独一层，由人拍定义后再挂上去。**待定**：L2 的临床定义（治疗起点、观察窗）由谁拍。

## 六之四、影像轴（契阔 2026-09-18：要纳入，按数据实际收敛）

**数据事实**：我们的语料是扫描 PDF，**里面没有 DICOM 影像文件，也没有任何影像标注**；`imaging_report` 是**文本报告**类别（每 400 例统计 458 份，本批约每例 1.1 份）。因此影像这条轴按"报告文本 + PDF 内嵌图"来做，不承诺图像模态。

| 做 | 内容 | 键来源 |
| --- | --- | --- |
| **影像题（已并入题库 Q10/Q11）** | 该病例有几份影像报告 / 最近一次影像报告的采集日期 | 文档类别计数与日期，机械可算 |
| **含图页指标** | 含图页占比 = 有图像对象且无文本记录的页 / 全部页；以及其中进了库的比例。这是此前人工核对发现的缺口"含图页没进库"的量化 | 页面对象与文本记录计数，零模型 |
| **`report_sections` 字段预留** | 影像报告是"检查所见 + 诊断结论 + 建议"的分段版面，几何层的列表头提取对它不适用；字段 `{document, section, text}` 先留，将来可独立成层 | 版面段落切分 |
| **不做** | 图像模态（CT/病理切片）：语料里没有 DICOM、没有标注，做不了也不承诺 | —— |

## 八、怎么重跑（中断后从这里接）

脚本本地在 `.local/`（gitignored，权限原因不入库），服务器在 `/tmp/ladder_scripts/`；
密钥在服务器 `/tmp/ladder_scripts/key.txt`（`run.py` / `agg.py` 默认读它，不需要在命令行传 key）。

| 本地文件 | 服务器名 | 作用 |
| --- | --- | --- |
| `bench_ladder_build.py` | `build.py` | 扫描批次 → 五版本载荷（v1~v5 + 反向 3）+ 结构化链 d1~d5 + 机械事实 `facts.json` |
| `bench_ladder_qbank.py` | `qbank.py` | 从机械事实出 12 例 × 6 题题库（含答案键与关键词型） |
| `bench_ladder_run.py` | `run.py` | 病例级 8 条件 × N 例，一次调用/例，打分并写 `results_main.json` |
| `bench_key_finalize.py` | `finalize.py` | 用两个独立强模型复核键 → `keys_final.json` |
| `bench_ladder_rescore.py` | `rescore.py` | 用定稿键重打分（不再调模型）→ `final.json` |
| `bench_ladder_agg.py` | `agg.py` | 队列级 11 题，正向 + 反向（`--reverse m1,m2,m3,m4`） |
| `probe_date_audit.py` | `date_audit.py` | 日期抽取校验（纵向时间前置） |
| `bench_ladder_driver.py` | `driver.py` | **一条命令跑完全部未完成步骤（每步有产物就跳过，可重复执行）** |

```bash

cd /tmp/ladder_scripts && setsid nohup python3 driver.py \

tail -f /tmp/ladder/driver.log        # 结果汇总最后落在 /tmp/ladder/REPORT.md
```

条件清单（固定，勿改口径）：病例级 `v1,v2,v3,v4,v5,v5_m3,v5_m2,v5_m1`；队列级正向 `d1..d5`，反向 `m4,m3,m2,m1`（m4 = 机器说明书，m3 = 溯源与状态，m2 = 单位归一，m1 = 格式统一）。
