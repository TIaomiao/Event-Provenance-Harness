## 论文概览

> **本节是当前工作稿：我们准备做什么、打算怎么验证。它是假设与方案，不是已验证结论。**

**工作题目**：面向任务的纵向 EHR 证据选择（Task-Conditioned Evidence Selection for Longitudinal EHR）

**一句话**：研究自然语言取数要求能否被正确解释并执行——在纵向 EHR 记录上选出任务真正需要的记录集合、时间点与来源，并如实交出未决状态。

**英文题目**：Task-Conditioned Evidence Selection for Longitudinal EHR

英文工作题目（未定稿）：*Task-Conditioned Evidence Selection for Longitudinal EHR*

**Motivation**（用户 2026-10-06 采用）

> In conventional data access, selection predicates such as fields, temporal windows, and aggregation rules are explicitly encoded in queries or application logic. In agentic data access, an AI system often has to infer these data-selection requirements from a natural-language task.

**含义**：同一批纵向记录，对不同任务可能应选择不同的时间点、记录集合或聚合方式。研究的是**自然语言取数要求能否被正确解释并执行**。不宣称传统数据库不支持这些操作，不把 SQL 与 AI 对立；不预设 LLM 必然失败，也不声称新颖性或方法增益已被证实。

**研究问题**

> 给定一个自然语言取数要求与一批冻结的纵向记录，系统能否被正确解释为明确的选择条件（项目、时间角色、时间窗、选择方式、范围、并列与缺失策略），并据此选出正确的记录集合，同时把值、单位、时间、来源和未决状态一并交出？

三个子问题：① 直接回答与「先计划再执行」在记录集合层面各自错在哪里？② 错误主要来自条件解释、程序执行，还是资料本身缺字段？③ 空集合、应保留未决、无效题是否被分开处理，而不是被最近的一条记录掩盖？

**输入与输出（第一阶段）**

| 项 | 内容 |
| --- | --- |
| 输入 | 已获准来源中的纵向临床记录（冻结范围 + 稳定匿名标识）＋ 自然语言取数任务 |
| 输出 | 选中记录集合；每条的值、单位、时间角色与来源锚点；明确的未决状态与原因 |
| 不做 | 病种标签、手术/治疗事件定义、模型训练、临床诊断解释 |

**基线（先跑通，不包装成创新）**

| 编号 | 条件 | 说明 |
| --- | --- | --- |
| R1 | Direct selection | 模型读任务与记录视图，直接返回记录集合、值/时间/来源与状态 |
| R2 | Plan then execute | 模型只输出结构化取数条件，由固定程序执行过滤、排序、选择与汇总。**R2 就是 baseline，不宣称新方法** |
| 诊断 | 人工明确的正确条件 → 同一执行器 | 用于分离「程序把正确条件执行错」与「模型给出不同条件」。不是独立模型对照，也不能用同一抽取器给自己建 gold |

Jev 是 baseline 跑通后的迭代组件，不阻塞当前任务；不为满足「用了 Jev」提前创建决策点。

**当前阶段（2026-10-06 收口）**：**明确任务域的选择检查已完成**——在给定记录视图、项目与时间角色等条件已由宿主声明的范围内，**未观察到 R2（先解释条件再执行）相对 R1（直接选择）的选择正确性收益**；扩到 10 个开发包、最多 21 条目标记录与 21 个采集日后两组仍都正确，差异为 0，且唯一被证实的缺陷在我方参考与定义。**当前满分是能力边界结果，不是方法增益**，不据此宣称新颖性。**新增的下一小步是有限的时间角色解释对照**：任务显式指定使用**采集时间**或**报告时间**，R2 需解释 `time_role` + `window` + `selection`，`project`、患者 scope、并列/缺失策略与安全规则仍由宿主给出；任务域不新增病种、手术/治疗起点、事件去重或多患者隐式范围推断。**Jev 仍为后续候选组件**，不在当前阶段接入。

**责任边界（本轮规格）**：模型只负责**用户任务需要理解**的条件与选择（R1 直接给出记录集合；R2 给出 `time_role` + `window` + `selection`）。`project`、`time_role`、`scope`、`tie_policy`、`missing_policy` 由**宿主绑定并在协议中声明**；值、单位、时间、来源由宿主按 `record_id` **统一展开**（两组一致，账本记录该选择）。这**不**等于“所有任务条件由模型自主推断”，也**不**等于“模型已独立核验原始 PDF 字段”。

**两层参考（本轮规格）**：

| 层 | 内容 | 不是 |
| --- | --- | --- |
| A 选择参考 | 在冻结记录表上按**任务条件**独立计算期望（`src/evaluation/selection_reference.py`，不调用被测执行器），保留状态、正确集合与未决候选；边界例用字面写明核对；与执行器的分歧必须报告 | 不是来源事实金标准 |
| B 来源事实核对 | 从**原页裁片**核对项目、值、单位、时间，并检查候选**遗漏**而不只核已抽出的行 | 自动提取不是人工 gold |

**开发覆盖（本轮规格）**：选包规则、种子、来源范围与哈希在**读取任何模型结果之前**固定；最多 10 个开发患者包，同一患者跨文档算一个包；每包保留 latest-before / first-after / all-in-window，并按实际资料增加端点、空集合、并列或精度题，每包最多 6 项；任务分**自然任务 / 同义改写 / 受控构造**分别计数；空集合不算不适用，身份缺失与资料不足分开；**全部标开发**，不使用既有独立验证集调试，也不按模型成绩挑病例。目标记录统计用**目标记录本身**的采集日，不用全病例相对日数替代。

**当前候选主张**（全部待检验，不预设正结果）

| 编号 | 主张 | 怎样会被推翻 |
| --- | --- | --- |
| S1（条件解释） | 自然语言取数要求中的时序约束（之前/之后/窗口、含不含端点）在直接回答条件下会被解释错 | 直接回答在记录集合层面已达同等结果，错误不集中在条件解释 |
| S2（集合正确性） | 检查具体记录集合而不只看 `status`，能暴露只看状态时看不见的选择错误 | 记录集合与状态判定结论一致，集合检查不增加信息 |
| S3（计划—执行） | 把条件外化为可校验结构再由程序执行，可减少选择错误并让失败可归因 | R1 与 R2 在相同输入、任务、预算和修复规则下无差别，或 R2 只增加成本 |
| S4（未决保留） | 并列与精度不足时保留未决，比任选一条更接近正确答案 | 未决条件下任选一条与保留未决得分相同 |

**未验证项（写作与汇报时必须保留）**

1. **没有人工金标准**：现有参考由规则/OCR 路径生成并标 `pending manual review`，不是逐页人工核对结果。
2. **开发集不是留出集**：当前只用少量开发包，不能冒充独立验证；正式留出集未启用。
3. **输入层尚未完全适配**：治理产物到研究输入的适配层只覆盖 `laboratory_report` 与单一目标项目；其他类别本轮未覆盖。
4. **参考与其中一个条件可能共享抽取器**：凡共享抽取器处，该条件在抽取类错误上不是独立测量，必须逐处说明。
5. **同一模型不是公平性充分条件**：输入、任务、资源与修复规则都要记录；provider 与部分服务端标识未知时不作家族推断。
6. **方法增益未证实**：本阶段只跑通流程并给出可归因失败，不给方法排名。

### 历史：证据关联候选 pilot（2026-10，已停止续跑）

> **本小节是历史记录。** 它描述的 B1/B1-V/B2/B3 条件与“证据关联”候选机制**不再是现役方案**，不再发布续跑安排。现役方案是本文件顶部的 R1/R2 任务选择 baseline；B1/B2/B3 的实测读数（含其参考与抽取器限制）保留在 `results/2026-10-02_evidence_association_pilot.md` 与 `results/2026-10-06_task_selection_baseline.md` 中作为历史证据与错误类型来源。

**最强反驳（历史）**：如果 B1-V 或 B2 已能稳定保持记录—值—时间—来源关系，候选机制没有新增价值；如果失败主要来自 OCR、输出截断或 parser 尚未接入，不能把它写成证据路由问题；如果有限补查只增加请求和成本，B3 不成立。

**候选机制**：在准备产物中显式保存记录—值—时间角色—来源范围的关联；运行任务前检查该任务需要的关系是否齐全；缺口只触发有限、可记录的 `lookup`、`reparse` 或 `defer` 动作。Jev 是动作选择器的一个可替换后端，与规则和普通 LLM 共用状态、动作、执行器和后置检查；不凭置信度发布事实。

**强基线与对照**：

| 条件 | 定义 | 当前用途 |
| --- | --- | --- |
| B1 | 原文 + 合理搜索、分页、通用计算；按统一任务契约回答并给证据 | 强基线 |
| B1-V | B1 加明确的证据范围、时间角色、未决和一次有限修正检查 | 核验基线 |
| B2 | 固定准备流水线，保留来源、时间角色、未决和可回查证据 | 准备基线 |
| B3 | 在 B2 上增加候选关联检查与有限补查动作；Jev 仅作动作后端对照 | 只有在开发集发现残余问题时实现 |

**初始任务与样本**：目标为 6 个开发包、12 个独立验证包；首轮取 2 个开发包，每包三题——A 指定采集窗口内符合数值条件的记录，B 截至某报告时点可获得的最近采集记录，C 候选“记录—值—时间”组合是否被资料支持。任务只针对冻结资料范围，不询问全病史首次事件；自然案例与人为构造核验命题分开统计。

**判定依据**：源记录字面事实先独立核对，任务答案由确定性程序计算；模型不能读取答案键。分别报告可核验任务成功率、内容正确率、可回答题的正确回答、不足资料上的错误确定回答、证据关联错误、技术失败和实际总成本。参考尚待核对时允许运行，但结果标为 `reference_pending`，不写成可信正确率。

**续跑安排（已停止）**：原“继续条件／退出条件”和“阶段顺序”（2 开发包 × 3 题 × 3 条件 = 18 条轨迹、再扩 4 包、最后 12 个独立验证包）**不再执行**。停止原因是 2026-10-06 的两批实测：M2 那批的参考分布退化且参考与 B2 共用抽取器，本批任务集在 2 条记录的开发包上没有区分度。历史读数保留，不再据此推进 B 系列条件。

**历史 pilot 状态（2026-10-02）**：CASE-102 与 CASE-167 的 18 条最终有效轨迹已完成，全部 HTTP 200；初步机械读数为 A 6/6、B 3/6、C 0/6。参考键仍待人工/原页核验，不能据此报告可信正确率。初版 B2 载荷曾复用参考抽取结果，已作废并用独立 line-level preparation 重跑；作废请求的费用保留在总账中，不进入比较表。

**C/B 开发口径（v0.2，2026-10-03；任务定义，不是人工金标准）**：

- **C** 只核验身份明确的记录—值—时间。`null` / `unresolved` 是处理状态，不自动构成矛盾；单位只在明确声明或数值换算要求中参与事实判定。候选必须带项目名和来源锚点；身份缺失返回 `invalid_task`，不强制归入 `supported` / `contradicted` / `insufficient`。CASE-102 旧题保持“候选构造错误”，不使用补齐后的候选反向给旧响应补分。
- **B** 只在冻结检验报告内，按明确关联的采集时间排序。不扩展到全病历，不用报告时间代替，不增加未提供的 as-of 截止时刻。并列记录全部保留；日期精度不足或无法确定先后的记录返回未决；来源定位可以代替内部 `record_id`。
- 以上口径只用于开发题、离线重评分解释和后续题卡；它们不冻结人工金标准。两项口径与 raw 测试许可均已在 2026-10-06 的接手基准中确认（详见 `CONTROL_PANEL.md`），不因更换执行会话重新索取。外发放行不由本口径决定，另见下面的输入模式说明与出站 guard 条件。

**离线修正状态（合成已覆盖；真实开发运行见 2026-10-06 M2）**：新增独立的合成候选规则和出站 guard。规则区分项目名、结果、单位和参考区间，支持单位单独占行；它不把参考区间下限当结果。`classify_c_candidate` 只检查结构、身份和缺失字段，不判断事实真假。合成测试覆盖参考区间、单位缺失、共享报告时间、采集/报告时间排序、并列、日期精度和身份缺失。出站 guard 区分 `synthetic`、`deidentified_test` 和 `raw_test`，默认阻止 raw OCR、`api_ready=false`、哈希不符、未批准 endpoint/pool profile、未知状态和缺少任务字段。2026-10-06 已用 6 个冻结开发包真实运行 B1/B1-V/B2（30 条可运行槽全部 HTTP 200），但**该批不能作方法比较**（参考分布退化、参考与 B2 共用抽取器、回答协议不稳），详见 `results/2026-10-02_evidence_association_pilot.md` 的 M2 小节。真实 pilot 旧输入、旧参考、旧响应和 v2 判读不变。

**最小资料卡（受控、已按实际哈希登记接受）**：CASE-167 的两条 HGB 项目—结果—单位—采集/报告时间卡，以及 CASE-102 的两条 HGB B 题时间卡，每卡 12 行，均只保留必要行定位。卡片入口为受控只读页 `http://127.0.0.1:8877/cards.html`，身份处理对照在同页 `#identity`，最终卡在同页 `#card-v03`（依赖本机 SSH 隧道，不进入仓库与 Pages）。用户已于 2026-10-06 完成目视查看与确认，两张 v0.3 卡按实际 SHA-256 登记为 `card_review_status=accepted`、`card_api_ready=true`（范围仅限这两张卡）；但未回原始 PDF 比对数值，因此**不构成人工 PDF 金标准**。用户在身份对照页确认 v0.2 卡路径上存在**真实姓名未替换**，因此完整 L2 继续保持 `NOT_SAFE`、不声明整份报告脱敏通过；**卡片通过不翻转整份 L2 的 `api_ready`**。

**卡片日期口径（2026-10-06 统一）**：卡片使用「**病例内相对日 + 原始时钟／原有精度**」。同一病例的所有相关采集与报告时间必须共用同一 anchor 与同一变换，并保持：相等关系、时间先后、日期/时间间隔、以及「采集早于报告」的角色关系；**原始只有日期时不得创造时分秒**。CASE-102 的既有相对日表示保持并已程序复核；CASE-167 原先整段删除采集日期的形态**不接受**作为 B 题的 deidentified 输入，已按同一口径重新派生为 `derived_evidence_card_v0.3`，两条采集记录分处不同相对日、先后可恢复。程序判定两卡上述不变量全部保持，raw 历史材料与旧响应未被修改。

**卡片级审核与放行（task-scoped）**：完整 L2 保持 `api_ready=false` / `NOT_SAFE`。卡片另有独立状态 `card_review_status` 与 `card_api_ready`，并在 `#card-v03` 给出六项验收表：`identity_leakage`、`task_fields_complete`、`time_order_preserved`、`time_interval_preserved`、`collection_report_relation_preserved`、`source_anchor_preserved`；取值只用 PASS / FAIL / NOT_APPLICABLE / UNKNOWN，且 **UNKNOWN 不自动当 PASS**。只有卡片自己的最终 body 满足「无不必要身份字段、必要项目/值/单位存在、B/C 所需时间关系保持、来源锚点仍可回溯、离线正文扫描通过」，并且用户复核通过后，才允许运行卡片级 `deidentified_test`。**卡片通过不翻转整份 L2 的 `api_ready` 状态。**

**外发许可与输入模式（2026-10-06 确认）**：负责人已明确允许测试阶段的 raw OCR 外发，脱敏产物优先，属非生产授权。`raw_test` 必须显式绑定该许可、来源范围、用途、目标 endpoint 和号池配置；`deidentified_test` 仍要求 `api_ready=true` 与匹配 source hash；未审脱敏卡不能自动放行。任何模式都禁止静默 raw 回退、生产发送或手动翻转 `api_ready`/`quarantine`。

**合成别名与任务判定矩阵（2026-10-03，NOT_RUN on patient data）**：固定 6 个合成场景、3 个别名、3 次重复，共 54 个逻辑请求。矩阵只测当前路由可用性、返回模型标签和固定合成任务的重复一致性；503 是服务失败，不是内容错误；provider 未返回时标为 `provider_unknown=true`。本轮结果不验证真实模型身份，也不支持供应商无关结论。两份资料卡的 24 个卡片逻辑请求保持 `NOT_RUN`，不因 raw 测试许可自动放行 deidentified 草稿。

号池反馈进一步确认：前缀是渠道标记，不是模型家族标记；`c-` 渠道已撤下。pricing 页面价格统一按人民币显示。合成矩阵中的 503 仅是探针时间点状态，不能写成永久不可用或模型能力失败。

## Benchmark v0.1 工作稿（阶段性外框）

> 本节保留为较宽的评测外框。当前具体实验以本文件顶部的 **R1/R2 任务选择 baseline** 为准；下面的 B1/B1-V/B2/B3 表格是历史条件定义，不再发布续跑安排。预算、样本量、任务规则和最终主指标需在开发烟测后冻结。

### 可执行的 AI-ready 定义

针对明确的使用任务，资料包具备可理解的字段含义、可区分的时间和状态、可回溯的证据，以及可重复调用的访问方式，使未参与准备过程的消费者 Agent 能按约定完成任务，而不需要开发者逐题修改资料或代码。AI-ready 是任务和条件相关的使用性质，不预设某种准备方式必然胜出，也不把一个全局 readiness 分数作为本轮结论。

### 第一轮任务顺序

- **T1 主实验：单病例事实与时间整理**。同一资料包完成极值/阈值计数/时间窗口任务，并返回结果、来源、时间角色与未决状态。
- **T3 诊断实验：证据核验**。对候选事实判断 `supported`、`contradicted` 或 `insufficient`，定位来源与时间/字段不一致。
- **T2 后续扩展：跨病例筛选与统计**。在 T1 闭环稳定后，以小队列测试筛选、计数与首次满足条件的日期整理。

资料包限定为冻结的患者检验报告范围；准备阶段不得读取留出题目的具体阈值、时间窗口、候选结论或答案。本轮累计调用沿用既有 100 美元范围，实际准备、查询、重试和在途请求统一记账。

### 比较条件

| 条件 | 准备与访问 | 地位 |
| --- | --- | --- |
| B0 | 一次性原文输入 | 可选诊断条件 |
| B1 | 原文 + 分块、检索、逐步读取和通用计算 | 主基线 |
| B2 | 固定的常规准备流程，保留来源、时间和未决项 | 强基线 |
| B3 | Harness + Agent：根据检查结果选择补读、重解析、回查或保留未知 | 被评系统 |

B1 允许合理访问，B2 不人为削弱已有合理准备能力；若 B2 已经足够，允许它胜出。B3 对 B1 的比较回答整体准备与使用是否有益，B3 对 B2 的比较回答准备编排、核验和修复是否带来额外价值。

### 第一轮主指标

主指标候选为“预算内可核验任务成功率”：结果正确、来源确实支持、单位和时间角色正确、相关未知项没有被错误补全，并在预算内完成。同时分开报告内容正确率、证据错误、不当确定回答、技术失败、准备/索引/查询/修复成本和人工时间。JCM 的 0–2 维度用于定义准备产物检查项，不直接作为主结果分数。

**本节要一起读的限定**：多层级处理是**候选消融**，不预设每层正收益，层数不是贡献；主题是「整体方案 + 可复用性」，不是「逐层涨分」。目标架构、代码存在、接口可调用与端到端验证是四件不同的事。

## 一、问题

真实医院的病历是**扫描 PDF**，不是数据库。要让它们成为「现成的 AI 能直接用」的东西，中间必须做一系列准备动作（把版面读成行、统一单位、标上来源、排好时间、写清字段含义……）。问题分两层：

1. **差异层**：AI-ready 与常规做法（不做准备，或按治理规范做常规准备）的**本质区别**是什么？好处落在哪个维度上？
2. **设计层**：把准备工作组织成可调用、可核验、可复用的系统（Harness），由 Agent 编排调用，能不能在真实任务上带来可测量的改善？

**不预设准备动作总带来正收益。** 现状是：AI-ready 更多是标签或人工等级量表；现有的对照实验多在「已经结构化」的输入上做。我们检索范围内未见同形工作，这是**检索覆盖内的待核缺口**，不是「无人研究」的证明。

待回答的七个问题（会议 §5.3）：

| # | 问题 | 现在能答到什么程度 |
| --- | --- | --- |
| 1 | AI-ready 的操作性定义是什么？面向哪种使用者与任务？ | 见「论文概览」的研究问题与候选贡献；面向科研资料整理与核验 |
| 2 | 与何种「非 AI-ready」或常规方案比较才公平？ | 已有两条对照默认稿（§七），未实测 |
| 3 | 核心优势是任务完成、少做准备、成本、稳定性，还是核对便利？ | 见「论文概览」的 H1–H5；每条主张各有独立定义与证据 |
| 4 | 什么证据能判定任务完成或结论正确？ | 已有三层答案依据默认稿（§八），未运行 |

## 二、目标使用者与使用场景

- **直接使用者**：需要从真实病历里取事实与统计的**研究者**（临床研究者与数据整理者），不是终端患者，也不是实时临床决策者。
- **初步场景**：**科研资料整理与核验**——给定一份或一批病历，取回一个事实、一张表或一个计数，并给出依据与未决状态。
- **候选任务**（待任务设计与师兄反馈；**不能写成已临床验证的需求**）：
  - **T1 单病例事实与时间整理**：某项目的极值、超阈值次数、某事件的最早/最近日期。
  - **T2 跨病例筛选与统计**：一批病例里有多少例满足某个条件。
- **下游消费者**：没参与建库的现成 AI / Agent，一次调用或多步调用（方式待定）。

| 环节 | 定义 | 现状 |
| --- | --- | --- |
| **输入** | 真实医院扫描 PDF（受控环境切片，已获数据许可） | 已有可用批次 |
| **准备产物** | 可复用的数据产物与访问接口：原文、结构化观测、单位归一、溯源与状态、机器说明书、纵向时间轴 | 已有实现，作候选组件 |
| **输出** | 答案 / 表格 + 依据（引用可解析）+ 未决状态 | 接口已实现 |

## 四、整体架构

**目标结构，不等于已经端到端实现。**

```text
科研资料整理 / 核验任务
          ↓
Agent：理解任务、选择步骤、在预算内编排
          ↓ 调用
Harness：文档读取与定位、提取与规范化、时间与来源关联、
         检索与分页读取、程序计算、格式与内容核验等可调用能力
          ↓
可复用数据产物与访问接口
          ↓
后续任务使用 → 答案 / 表格 + 依据 + 未决状态

旁路：评测器检查任务是否通过，并独立记录资源代价与失败。
```

**角色分开，但不要求建立多个 Agent**（可以复用同一基础模型或同一进程）：

- **准备流程 Agent**：把原始文档变成可复用产物。
- **下游任务消费者**：使用产物完成任务并给出依据。
- **自动实验驱动器**：按协议跑条件、做自检、产出只含聚合数字的结果。

**复用的含义必须可检验**：跨病例、跨未见任务复用同一套组件，减少逐题定制；**准备阶段不得读取留出题目或其答案**。

## 七、方法与对照

**当前 pilot 使用三组比较；后续若有残余关联错误，再加入 B3。**

| 对照 | 它代表什么现实做法 | 必须包含的能力 | 已知风险 |
| --- | --- | --- | --- |
| **B0 一次性原文输入** | 不做额外准备 | 原文直接输入 | 只作诊断条件，不能代表合理的原文访问 |
| **B1 原文 + 合理访问** | 不做准备，但允许正常使用工具 | **分块、检索、逐步读取、通用计算**；一次性输入只作**诊断条件** | 若不给这些能力，规模一大就不可比 |
| **B1-V 核验基线** | B1 + 明确证据范围、时间角色、未决和一次有限修正检查 | 与 B1 相同的来源和通用工具 | 规则/提示增强本身可能解释一部分差异 |
| **B2 可复现的常规准备流水线** | 按常识整理一遍 | 保留合理的字段说明、单位、来源、时间和未决项 | 边界需在烟测后冻结，不得人为削弱 |
| **B3 Harness + Agent** | 根据检查结果选择补读、重解析、回查或保留未知 | 与 B2 使用相同的通用访问与计算能力 | 组件编排收益待验证 |
| 少量独立原文核对 | 全人工整理的代表 | 抽样核对，不作为必做的大规模基线 | 人工核对不是自动无误的金标准 |

**B1、B1-V、B2、B3 都允许分块、检索、逐步读取与通用计算**；若加入专属索引 / SQL 工具，必须分开报告「整体系统效果」与「表示 / 工具」两个因素。B2 如果已经足够，允许它胜出。

## 八、指标、答案依据与成本

**主指标候选**（草案）：**给定预算内、通过预定核验的任务比例**。正确性与接口完成分开；成本、人工介入、核对时间各自独立成维度，**不合成任意总分**。正式验证前冻结主指标与容差。

| 维度 | 定义 | 失败怎样记录 |
| --- | --- | --- |
| 接口成功 | 请求返回且符合输出接口 | **接口/工具失败**与**格式失败**分别记 |
| 内容正确 | 与答案依据在预定容差内一致 | **答错**与**错否定**分别记 |
| 适当拒答 | 依据不足时说明不知道 | 该说不知道却编 → 记为错答；不该拒答而拒答 → 记为覆盖缺口 |
| 运行失败 | 预算耗尽、超上下文、进程错误 | 与答错分开单列 |
| 成本 | `C_total(N) = C_prepare + C_index + Σ(C_query + C_retry/repair)` | 人工时间另报；未知成本标「未知」 |
| 核对便利 | 引用可解析率 + 走到原文的步数（**代理指标**） | 真人计时的「医生核对时间」未做 |

**答案依据三层，分开报告**：L1 机械层（格子几何，零模型产出）／ L2 模型层（比被测更强的模型出候选，记录版本）／ L3 人工层（抽样核对）。**造键的模型必须 ≠ 被测模型，并留一个没参与造键的模型做留出评测。** 另设**独立于被测库**的程序 / SQL 对照键。

## 十、公平性

| 问题 | 默认工作稿 |
| --- | --- |
| 原文那一方允不允许分块 / 检索 / 逐步读取 | **允许**；一次性输入作诊断条件 |
| 准备后那一方允不允许查询 / 计算工具 | 允许**通用**计算；专属 SQL / 索引须分开报告 |
| 双方预算怎么匹配 | 相同**预设资源上限**下比较，报告**实际消耗**；不强迫各方花完同样 token |
| 建库成本计不计入 | **计入**；摊销次数**预先规定**，不挑对本方法有利的 N |
| 病例数与题目数 | 待定；**留出未参与开发的病例与题目**做验证 |

| 脱敏与授权 | **所有条件的共同前提**，不为制造分数差而关闭 |

## 十一、候选消融：多层级处理

已有实现是一条**严格超集**链：生数据 → 格式统一 → 单位归一 → 溯源与状态 → 机器说明书 → 纵向时间轴。每个版本保留上一版全部内容、只加一样东西。

**归因的限度（重要）**：超集构造消除了「换了别的东西」这一类混淆，但**不足以把差异唯一归因于单一组件**。至少还有三个未被控制的量会同时变化——**输入总长度 / 材料总量**、**预计算与物化的程度**、**提示长度**。因此：

- 超集差值只能读作「**在这一串构造下，加上这一样之后结果如何**」，不能读作「这一样单独值多少分」。
- 要支持组件级归因，至少还需要**反向拆件**（从最完整版本逐样拿走）与**长度/预算匹配的控制条件**；这些尚未做。
- 若准备材料里含与测题直接对应的预计算摘要，必须写明这是「预计算 / 物化」的成本收益，不是模型推理能力的提升。

**定位**：这是用来**选择性解释组件作用**的候选拆解，**不是**论文必须成立的结论序列，也**不预设每层正收益**；层数本身不是贡献。固定准备策略，**不得读取留出题目或其答案来定制材料**。

已有探索性结果（2026-09-19，`results/2026-09-19_ladder.md`）：批次 984 例 / 5,255 文档；病例级 12 例 × 11 题 × 9 条件 × 3 次重复，消费者与建库过程无关（建库为零模型机械脚本）。生数据 61.6% → 机器说明书 73.0% → 纵向时间轴 81.9%，前四层单独看几乎不动分。**这些数字是探索性结果**，只用来支撑「分层归因这个做法可跑通」，并带着上面那条归因限度一起读。

## 十三、当前局限

- **无医生金标准**：内容正确率与临床等价匹配做不了；指标全部落在「机械可判 + 可核对」这一层。
- **单人核对答案键**：报不出标注者间一致性。
- **消费者模型**：已有三家命名均为 Gemini 系，**家族独立性未证实**，真实返回型号 / 提供方 / 版本未记录；因此不得声称模型无关。
- **主表未填**：完整主张、对照、指标和独立参考协议仍是草案；选题 pilot 的机械读数只作诊断，不能占主结果位置。
- **完整对照未冻结**：当前只完成 B1/B1-V/B2 的两个开发包 pilot；12 个独立验证包和 B3/Jev 尚未运行。
- **队列级结论有适用条件**：限定在「指定模型、指定配置、单次输入」；分块、检索、逐步访问、索引与计算工具**均未被排除**，不得写成「原文物理上做不了」。
- **组件未联通**：现有原型是局部模块，不是完整的 Harness + Agent；接口可调用不等于端到端可用。
- **本地未核**：受控端服务器运行目录、计划任务与服务状态本轮未访问。
- **影像模态不做**：语料是扫描 PDF，没有 DICOM、没有影像标注；影像只做报告文本题、含图页指标与字段预留。

## 十四、待上级判断（不自行裁定）

1. **医疗任务的专业含义与合格参考标准**：哪部分必须由临床专家裁定（例如治疗起点的定义），开发侧不得自行拍定。
2. **超出现有授权的动作**：数据访问扩展、对外发送、新增付费调用预算、额外人工标注、计算资源、投稿承诺。已获明确的测试阶段 raw OCR 外发不在此列，但仍须按上面的输入模式绑定许可、范围、用途、endpoint 与号池配置。
