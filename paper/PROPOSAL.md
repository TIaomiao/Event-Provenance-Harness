## 题目

**AI-Ready EHR at Scale: Which Data-Preparation Steps Actually Make Real Hospital Records Usable by Off-the-Shelf Agents?**

中文：**真实医院数据要加工到哪一步，现成 AI 才能直接用？**

## 中心命题

**从扫描件到可用数据这段路上，哪些准备动作值钱、各值多少。**

"AI-Ready"目前被当成一个标签或人工量表；真实医院数据的加工链（版面理解、单位归一、溯源、状态码、说明书）每一步都被默认为有用，**没有人量过每一步各值多少，也没有人量过它们在多大规模上还成立**。我们把它做成一条可复现的曲线：五个严格超集的数据库版本 × 五个指标 × 病例级与队列级两个尺度，配反向拆件（从最完整的版本一次拿走一样）。

主张与 FHIRBench 型工作的区别是**比的是哪一段**：FHIRBench 比的是"已经是结构化的数据怎么序列化"；我们比的是**扫描件 → 能用的数据**这一段，而版面污染、印章、定性结果、页码误入、单位印刷形全都在这段里。

## Motivation

**M1（真实原生数据）。** 现有工作（FHIRBench，medRxiv 2026-07-14.26358020）用的是 **100 个合成 FHIR bundle，输入已经是结构化的**；我们的输入是真实医院扫描 PDF（33,456 例 / 410,467 文档 / 2,130,171 页已处理，OCR 覆盖 90.8%），从扫描件到可用数据中间那一段没人量过。

**M2（队列级）。** 临床真正要的是队列级问题（"这批人里有多少……"）。实测：**原文在 10 个病例就到上下文上限，12 个直接 HTTP 400**；结构化层一次装下整批 **984 例**。在 33,456 例的规模上，原文不是"更贵"，是**物理上不可能**。

## 贡献（按证据分级）

1. **主贡献｜准备动作的归因曲线（真实扫描件，不是合成结构化输入）。** 五版本严格超集阶梯（生数据 → 格式统一 → 单位归一 → 溯源与状态 → 机器说明书）在**同一批次、同一批问题、同一个没参与建库的消费者模型**上逐层测量，配反向拆件给出"每一样各值多少"；五指标覆盖做对率、费劲程度、错答结构（含错否定）、该说不知道时、可核对性（引用可解析率 + 走到原文的步数）。答案键由几何层机械产出、零模型出键，并用独立口径与两个不同家族模型的审计交叉验证。
   *诚实说明*：FHIRBench（medRxiv 2026-07）已经做过"格式决定可用性"的比较并得出"更紧凑的格式更好"；另一篇 FHIR 序列化工作（medRxiv 2026-08）比较格式相关的可读性。**我们的增量在对象与维度**：对象是真实扫描 PDF、维度是五个准备动作 × 五个指标 × 两个尺度。这一条属于**增量，不是全新问题**。

2. **机制｜队列级可用性是一个门槛问题，不是一个分数问题。** 用同一批问题给出可复现的容量对比：原文 ≤10 例可答、12 例超 1,048,576 token；结构化层装下整批 984 例且基本正确；33,456 例规模上原文约 6.4 GB ≈ 21 亿 token。由此得到设计约束：**AI-Ready 层必须叠加在原文之上，不能替换原文**（替换即变成有损摘要）。
   *诚实说明*：`HoloBench`（arXiv 2410.11996）已建立"上下文变长时聚合退化、max/min 抗退化"的观察，我们的队列级结果**复现了同一现象**。增量在"容量门槛"这一维度。

3. **对象｜真实原生数据上的临床契约层。** 溯源字段、`answer_status`（**"确实没有" vs "没抽到" 分开**）、定性结果（阴性/阳性）与参考区间，是 FHIRBench 那类比较里不存在的维度；数据集本身按可复现协议构造：机械答案键 + 三层答案键（L1 机械 / L2 强模型候选 / L3 人工核）+ 几何层 recall 的独立口径校准。
   *诚实说明*：EHRSQL / MIMICSQL / MedAgentBench 都假定数据库已存在，因此"契约层"本身不是新发现；它的价值在于**这是真实扫描件上的契约层**，并且被当作可测对象使用。

## 契阔（2026-09-18）追加的两条轴

**轴 1｜纵向时间（"medical 的纵向序列，需要对时间应对"）。** 两种落法，区别在**实验里变动的是什么**：

- **只做题型族**：阶梯仍是 5 层，时间只体现在问题上（T1~T5：最早采集日期、检验与医嘱同日天数、最小值出现在哪天、队列首末间隔、先正常后异常的跨日变化）。回应的是"我们问了时间题"。
- **做第六层 v6 = v5 + 时间轴**：库里再加一块**已经把时间算好的材料**（每条观测绑 `date`/`date_role`/`day_index`，每病例一段 `timeline` 与 `timeline_summary`），v6 与 v5 的差就能干净归因到"时间加工"。回应的是"库能应对时间"。反向多一个点（v6−时间轴 = v5）。
- 共同前置：**日期抽取校验**（真实扫描件上的日期常缺标签）。
- 我们建议做 v6（且它天然包含题型族），完整对比与代价见 [AI_READY_PLAN.md](AI_READY_PLAN.md) 六之二。

**轴 2｜影像（"后续加点影像"，要纳入）。** 预留已具体化为四件事：① 影像题 2~3 道（份数／最近一次日期／检查部位关键词，键走文档级机械操作）；② 版面层预留 `report_sections`（检查所见 / 诊断结论 / 建议），本轮不进阶梯；③ 把"含图页占比"量成指标（对应已发现的 AI-Ready 缺口"含图页没进库"）；④ 真正的图像模态（CT/病理）本轮不做，写进 future work 并写清前置条件。

**题的临床化与自动研究（autoresearch）接入**：两者同向、不冲突，但要处理一个张力——临床化会让答案键不再"零模型"。做法是**分层题集**：L1 机械题集（现有 11 题 + T1~T5，键零模型）作主结果；L2 临床题集（3~5 题，键按三层协议：强模型候选 + 人工核）作辅助结果，并标注键的来源。详见 [AI_READY_PLAN.md](AI_READY_PLAN.md) 六之三。

## 与既有工作的边界（动笔前必须引用）

| 相邻工作 | 占据了什么 | 与本工作的关系 |
| --- | --- | --- |
| **FHIRBench**（medRxiv 2026-07-14.26358020） | 100 个**合成 FHIR bundle**，4 模型 × 3 任务，比序列化格式，结论"紧凑格式更好" | **必须引用。** 它比的是"已结构化的数据怎么序列化"，我们比的是"扫描件 → 能用的数据"这一段 |
| **HoloBench**（arXiv 2410.11996） | 长上下文聚合随规模退化、max/min 抗退化 | **必须引用。** 我们队列级复现同一现象，不得声称新发现 |
| Context-Dependent FHIR Serialisation（medRxiv 2026-08-05.26359794） | 序列化格式对可读性的影响 | 共享"格式决定可用性"的论点，对象是 FHIR 而非扫描件 |
| SLIDERS（arXiv 2604.22294） | 6~11M token 上的结构化抽取与编码对账 | 说明长上下文抽取已有系统级工作，我们只做度量层 |
| EHRSQL / MIMICSQL / MedAgentBench | 假定已有数据库/表格 | 说明"契约层"不是新贡献；也说明我们的对象在前一步 |
| J Clin Med 2026《From Medical Records to AI-Ready Data》 | 人工 0–2 级 AI-Ready 量表 | 我们主张的正是**量表 → 可复现度量**的替换 |
| ACIE / CCLM 2025 | 抽取质量与跨实验室可比性 | 背景：抽取准确率已不是主要错误源，重心应在可用性与成本 |

## 数据优势与边界

优势是**真实原生数据 + 纵向结构**：扫描 PDF、印刷表格几何、印章注释层、19 类文档、同一患者多时间点。这是师兄与契阔都点名的差异（"我们是真实的原生数据，更具有参考价值以及难度"）。

边界：
- **无医生金标准**：内容正确率与临床等价匹配做不了；指标全部落在"机械可判 + 可核对"这一层。
- **单人核对答案键**：报不出标注者间一致性（κ）。
- 几何层逐项 recall 88~99%，绝对做对率带不确定度；**跨版本比较不受影响**（所有条件共用同一键）。
- 本轮 1 个消费者模型（网关型号逐轮记录）；换模型重复是必做项而非可选。
- 印章（BJCA 注释层）经实测**不遮挡文字**（去除前后 6 页暗像素 −9~+5 像素），治理流水线已实现其去除；它不是 AI-Ready 的缺口。

## 必须证明的三件事

1. **曲线形状稳定**：换消费者模型、换题目批次，哪一层值钱、哪一层不值钱的**形状**不变（不是单点数字好看）。
2. **增益来自那一层本身**：超集与拆件条件的差异不能来自上下文长度或 token 预算。
3. **可核对性可人工复现**：引用可解析率与定位步数要能用原 PDF 红框对照抽查复现。

若这三件事不成立，主张应降为"单中心真实 PDF 切片上的一次分层可用性测量"，不能宣称通用 AI-Ready 评测协议。

## 对齐问题（下次见师兄/契阔时问）

1. **时间轴做第六层（v6）还是只做题型族？** 我们建议 v6——契阔说的是"需要对时间应对"，那是要求库能应对时间，不只是问时间题；完整对比见 AI_READY_PLAN.md 六之二。
2. **临床题的边界**：L1 机械题集作主结果、L2 临床题集作辅助结果这个分层可以吗？临床题的具体定义（治疗起点、观察窗、跨阈值）由谁拍？
3. **autoresearch 接入指哪一种**：把实验协议做成 agent 能自动跑的形态（现在的 `driver.py` 已是雏形），还是把数据库做成 agent 能自己提问、自己算、自己核对的**查询接口**（SQL / 工具调用）？后者需要额外的接口层，工作量不同。
4. **影像纳入到什么程度**：本轮加"影像题 2~3 道 + 含图页指标"够吗？`report_sections`（所见/结论/建议）是留字段还是本轮就做进某一层？
5. **医生核对时间**要不要真人小样本实测（例如 30 条答案、两位医生计时）？现在只有代理指标。
