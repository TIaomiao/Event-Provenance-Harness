# Benchmark 主表设计草案 v2（会后工作包 C）

> **会议依据**（19:41 / 20:45 / 27:49）："我们做实验做表，它一定是去证实上面的一个 motivation""根据这个出发点，才去看要做这个 benchmark 那个表单""AI ready 跟不 AI ready 的本质区别是什么？如果有好处，怎么通过实验指标去体现？"
> **要求**：**先设计主表，先不填成绩。** 每一行 = 一个可检验主张；每一列都必须能回答"怎么算成立、怎么算失败、不能据此说什么"。
> **完成判据**：每个指标都对应一项具体主张；能够判断正向、无差异和失败三种结果；经师兄对齐后再定运行规模与消费者。

**填写规则（本草案先立规矩）**

1. **一行一个主张**：不许一行同时声称"更准 + 更便宜 + 更省人工"。
2. **三态必须可判**：正向（差异显著且方向稳定）、无差异（跨模型/跨题目都测不出差别）、失败（加了准备反而更差）。**"无差异"和"失败"都要能写进结论。**
3. **不许事后改口径**：键、题目、分母、筛选规则一旦定稿，改动必须记录并重跑全部条件；不许为了让结论好看而删题或换分母。
4. **格式失败与答错分开**（本轮已实测出现：同一条件有一次整段不按接口返回）。

## 二、对照的三条候选（**尚未选定，会议要求先定对照**）

| 候选对照 | 它代表什么现实做法 | 公平性要点 | 已知风险 |
| --- | --- | --- | --- |
| **B1 原始扫描文本** | "不做准备，直接给 AI" | 双方都要能塞进上下文；原文在规模上会先撞上下文上限——要么限制病例数，要么承认它是"做不了"而不是"做得差" | 规模一大就不可比 |
| **B2 常规 ETL / 仅格式统一** | "按常识整理一下" | 必须说清"常识整理"到底包含哪些动作，否则对照不可复现 | 边界模糊，容易被质疑是稻草人 |
| **B3 全人工整理** | 医院数据治理的标准做法 | 人工成本要计入（时间/人数），否则"省钱"的主张不成立 | 我们没有全人工金标准，只能小样本做 |

## 三、公平性问题清单（会议 §6 工作包 C 明确要求补清）

| 问题 | 为什么影响结论 | 待定选项 |
| --- | --- | --- |
| 给原文的那一方**允不允许分块 / 检索**？ | 允许分块+检索，原文的规模劣势会大幅缩小 | 允许（多轮/工具）／不允许（单次塞入） |
| 准备后的一方**允不允许查询 / 计算工具**？ | 允许工具时，"结构化好"可能只是因为工具好 | 允许／不允许 |
| 双方**预算怎么匹配**？ | token 不同会造成"我们只是花得多"的攻击 | 等 token ／等调用次数 ／等人民币 |
| **建库成本计不计入**？ | 若不计，"省钱"主张站不住 | 计入（一次性摊到 N 个查询）／不计入 |
| 病例数与题目数 | 规模会影响聚合题的可答性 | 待定（已实测：原文约 10 例到上限） |
| 消费者模型数量与家族 | 单一模型 = 不可复现的结论 | 至少 2 个家族（本轮 3 家全是同一家族，是已知短板） |

## 四、已有素材怎么放（**降级为预实验，不占主结果位置**）

| 已有素材 | 会议后的定位 | 可以怎么用 |
| --- | --- | --- |
| 旧抽取 benchmark（引用/值/时间接地那套） | **前期预实验** | 作为"我们已有的工程能力"在方法一节交代，不进主结果 |
| 六层超集曲线（2026-09-19） | **探索性结果** | 作为"分层归因这个做法可跑通"的证据；**层数与各层地位待新问题定义确定** |
| 队列级容量实验（原文 10 例上限、结构化 984 例） | 探索性结果 | 用来支撑"规模上做不了"这一条，但要与 HoloBench 的既有观察一起写 |
| 答案键三层协议（机械 / 模型 / 人工） | 可复用资产 | 直接进新主表的"判定依据"列 |
