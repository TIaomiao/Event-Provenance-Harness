# KDD 目标论文 Idea：三轮打磨后的候选版本

日期：2026-09-08。目标会议：KDD 风格的计算机会议；具体届次与截稿日期待核对。KDD 2026 Research Track 的公开投稿周期已结束，因此本文不把当前方案写成“赶 KDD 2026”。

状态：**候选研究设计，不是已确认论文贡献。** 目前没有真实模型 A/B 结果，也没有独立测试集上的效果证据。标题、动机和创新点需要在与师兄对齐、最近邻全文核验和实验后继续收紧。

## 最终候选标题

**Event-Provenance Harness: Query-Conditioned Structuring for Verifiable Analytics over Real-World Longitudinal EHRs**

中文工作译名：**事件来源感知 Harness：面向真实纵向 EHR 可验证分析的查询驱动结构化**。

标题中的 Harness 只是把工作放进 Agentic Data Systems 的语境。论文真正要证明的是：事件身份、时间角色和证据来源组成的数据基座，配合查询驱动的结构化与执行评测，是否能让 Agent 在真实纵向 EHR 上更可靠地完成分析任务。

## 中心命题

真实纵向 EHR 的瓶颈不是把 PDF 转成 JSON，而是把分散、重复、冲突且时间含义不同的证据组织成可验证的事件。我们提出一个事件来源感知的 Harness：它按分析任务选择和物化所需事件，显式表达事件身份、时间角色、来源与不确定性，并在执行过程中用独立评测器检查结果。核心效果须在相同模型、相同合法证据和可比预算下验证。

## Motivation

1. **真实 EHR 的错误发生在关系层。** 同一指标可能在多份报告中被重复引用，也可能在不同时间真正复测；采样时间、报告时间、记录时间和文档时间并不等价。只做键值抽取、文本 RAG 或直接生成表格，可能得到正确的项目和值，却把时间、来源或事件身份配错，合并掉应保留的观测，或者生成没有证据支持的事件。这会直接破坏纵向分析。

2. **Agent 研究正在从“模型会不会回答”转向“数据和执行机制能否让结果可验证”。** DataSpace、ClinLens、HealthAgentBench 和 Harness-Bench 等工作显示，异构证据发现、长程时间语义、执行轨迹和独立 evaluator 已成为主要瓶颈。HealthFlow 已覆盖多 Agent EHR 分析，Agentic Context Cracking 也开始研究查询驱动的非结构化数据物化。我们需要把问题进一步具体化到真实 PDF EHR 的事件身份、时间角色与来源关系，并证明这些关系会改变答案质量和成本。

## 三个相互依赖的创新点

### 1. Temporal-Provenance Event Identity Layer

提出事件级表示和身份关联机制，把一次观测表示为：事件类型、项目、值、单位、事件发生时间、文档时间、来源页/bbox/evidence id、重复/冲突关系和不确定性状态。核心算法或约束要回答：

- 两份文档是在重复描述同一次事件，还是记录了新的复测？
- 时间属于采样、报告、记录还是仅文档生成？
- 多个值冲突时，哪些证据应并列保留，哪些关系应标成 unresolved？

这不是“输出多几个字段”。它必须产生可判定的事件身份和关系决策，并能被 evaluator 单独计分。当前工程已有 bbox、时间候选和事件表接口，但事件角色、行绑定和身份归并尚未完成。

### 2. Query-Conditioned, Uncertainty-Aware Event Materialization Protocol

给定一个分析任务，Harness 根据任务需要和当前不确定性选择证据、物化事件和触发补查；不预先把所有病历变成一张静态大表。若某个时间或来源关系会改变答案，才追加相关证据或模型调用；无法消除歧义时保留 unknown / conflict，而不是猜测。每一步保存可回放的事件版本、证据引用、触发原因和预算消耗。

它借鉴 Agentic Context Cracking 的“查询触发结构化”方向，但研究对象从通用文档缓存推进到纵向 EHR 的事件身份和时间—来源约束。若最终实现只是普通分块、检索和重试，这个创新点不成立。

### 3. Execution-Grounded EHR Harness and Evaluator

建立可复现的任务协议和执行评测器：每题规定匿名病例证据、目标事件 schema、时间可见范围、输出格式、参考答案和预算；运行时不给 Agent 参考答案。评价分解为值/单位、时间绑定、来源支持、重复观测保留、错误合并/拆分、漏事件、额外生成、适当 unknown，以及 token、调用、延迟和失败类型。

真实肺癌 PDF 用于反映实际文档长度、版式和重复分布；合成或程序化扰动用来控制乱序、复制报告、同值复测、冲突时间和缺失时间。受隐私限制，公开范围可以是任务 schema、评测器、合成伴随集和聚合结果，真实病例只在获准环境中评价。

第三点不是把“做了一个 benchmark”当作独立包装，而是让前两点的效果可以在执行中被公平、可解释地测出来。若没有独立参考答案和可复现 evaluator，只能称为系统原型。

## 研究问题与实验结构

### 研究问题

在相同模型、同一批合法证据和可比预算下，加入事件身份/来源层和查询驱动的证据组织，是否能降低真实纵向 EHR 的值—时间—来源错配，同时保留真正的重复观测，并改善质量—成本曲线？

### 逐步实验

1. **诊断基线**：在可直接核对的重复检验任务上比较规则/现有解析器和同一模型直接抽取，记录值、时间、来源、漏项和多项。
2. **事件身份小试**：加入事件身份层，构造同一事件多文档引用、同一项目不同时间复测、同值不同时间、冲突来源和 unknown 五类场景。
3. **查询驱动物化**：改变任务要求的事件集合，比较预先静态结构化和按查询物化的质量、调用成本与跨任务复用。
4. **主实验与消融**：在按病例划分的独立评价集上比较完整方案、去时间关系、去来源检查、静态结构化和直接抽取；至少报告质量—成本曲线。
5. **稳健性**：按文档长度、重复程度、时间歧义和 OCR 质量分层，说明何时有效、何时失败。

“几轮实验”是五种目的，不是固定五次运行。结果可能推翻当前假设，届时应收窄主张。

## 为什么这三点不是增量功能

真正的贡献必须具备以下证据链：

`事件身份可判定` → `查询触发哪些事件被物化可解释` → `执行 evaluator 能把关系错误与普通抽取错误分开` → `在真实数据和可比预算下出现稳定差异`。

仅增加多 Agent 角色、输出 JSON、添加时间列、增加来源字段、换更强 API、加入反思重试，都不能单独作为创新点。它们最多是实现手段或对照条件。

## 强度边界

如果最终只能完成时间适配、规则归并和一组小型重复检验实验，论文主张应写成：

> 在单中心匿名纵向肺癌 EHR 开发切片上，对事件身份与时间—来源匹配进行一次受控消融，观察其对结构化事件质量和成本的影响。

此时不能写“通用 AI-ready substrate”“普遍降低 EHR Agent 错误”或“达到 KDD 级通用 benchmark”。要达到完整 KDD 论文强度，至少还需：

1. 机制上确实区别于普通 RAG/ETL/去重，并有可回放的事件身份与查询决策；
2. 独立病例评价集、可信参考答案和分层指标，能区分身份、时间、来源、漏项和额外生成；
3. 固定模型与预算下的基线、消融、成本曲线和最近邻可比实验，最好覆盖不止一种任务或难度层。

## 向师兄确认的三句话

1. 您希望主贡献落在事件级数据表示、查询驱动 Harness，还是执行评测协议？我把三者组织成一条链，但需要确定论文主轴。
2. 您上次说的“多时序、模型层、protocol”具体对应什么机制？有没有最接近的论文或方法图？
3. 重复检验适合作为第一轮切入口吗？KDD 目标是下一届周期还是其他投稿窗口，下一阶段您希望我先拿出机制原型、评测器还是最近邻对照？

## 当前结论

**结论：** 这是目前最值得继续打磨的 KDD 候选框架，但还不是可以直接承诺投稿的完整 idea。

**依据：** 它把现有真实 EHR 工程优势转化为事件身份、查询物化和可验证执行三层研究对象，能与 DataSpace、ClinLens、HealthFlow、Agentic Context Cracking 等趋势对齐；同时保留了可被实验推翻的主张。

**置信度：** 研究定位中等；三项机制的新颖性与效果未知。

**下一步：** 先让师兄确认主轴和术语，再用合成任务打通事件身份、时间来源匹配和 evaluator；之后再决定是否进入真实模型调用。
