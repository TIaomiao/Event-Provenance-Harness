## 三、一问就答（背这些）

### 主表与结论

**Q：主表现在说明什么？**
A：只有一条：**契约写对之后，前沿模型的抽取是可追溯的**——引用、时间、值都 ~100%。
真正会坏的是工程环节（大病例一次调用吐不完）。

**Q：那不就没内容了？**
A：**是。**这就是我今天要找你商量的：要不要加难度、换表、还是换角度。

**Q：三种问法为什么分不出来？**
A：因为**原先的差别是我自己造成的**。旧提示词没说清时间怎么引，导致只有"整病例一次问"会出错。
写清之后三种问法都是 100%。

**Q：那"跑不出来"是怎么回事？**
A：一次调用要吐出整个病例的检验行。CASE-100 真值 514 行，`max_tokens=16000` 装不下，
返回的 JSON 断掉、解析失败 → 这个病例 0 行。提到 64000 后 CASE-02/CASE-09 从 0 行恢复到 286/291 行（真值 290/293）。
**而且每次跑失败的病例不一样**（CASE-04、CASE-09 两次运行之间状态翻转），所以这一格本身也有噪声。

**Q：把失败病例算 0 分和不算，差多少？**
A：**差一倍**：算 0 分是 40~48%，只算跑通的是 76~93%。这就是必须单列的原因。

### 数据与真值

**Q：2518 行这个真值怎么来的？**
A：几何聚类，不靠人工。每页把格子横坐标做直方图，连续密集的一串算一列；值列是"六成以上是纯数字、位置在页面中右部"的那一列；再按纵坐标把值格聚成行。**主动说**：这个真值还没校准，CASE-01 出现 122%（模型抽出的行比真值还多），说明它至少在那一个病例上漏数了。

**Q：12 个病例太少。**
A：是少，池子里 200 个，铺开约 $37。

**Q：为什么只用一个模型？**
A：用的最便宜那个。换模型要重测所有列。

### 方法

**Q：你怎么保证引用的行是真的？**
A：`source_refs` / `time_refs` 都写成 `DOC:L行号`，评分器把行号解析回原文，再比对内容。
行号不存在 → 引用不可解析；行号存在但内容对不上 → 字段接地失败。

**Q：时间为什么单独一个 `time_refs`？**
A：因为文档里**值和时间的来源物理上不在同一行**（值在表格格子里，时间在页脚）。
实测还有一层：538 个时间失败的行里，**302 行所在的文档里根本没有哪一行同时含日期和时刻**——
所以 `time_refs` 必须允许指向多行（日期一行、时刻一行），和 `source_refs` 要写成"证据集合"是同一类问题。

**Q：值接地那个 82% 是什么？**
A：**已经撤回了。**那是"逐字相同"的判定，文档写 `5.6`、模型写 `5.60` 就判它不接地，可这是同一个数。
改成"数值相等"之后是 **99~100%**。逐字那一列保留作脚注：差的 12~14 个点全是尾零/千分位/前导零，且都在模型自己引用的文档里。
