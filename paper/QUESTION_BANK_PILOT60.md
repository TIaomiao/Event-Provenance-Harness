# 试跑题库 v1（60 题）：设计、判卷规则、谁来核

师兄的配比是 30 算一下 / 20 查一下 / 10 库里真没有。
我们落成：**每个病例 5 题（3 算一下 + 1 查一下 + 1 真没有）× 12 个病例 = 60 题**。
（算一下占 60%，比他要求的"过半"更高。）

---

## 一、三条硬约束（这是"不用医生"的前提）

| 约束 | 为什么 |
| --- | --- |
| **阈值必须写进问题里** | 实测：检验报告里的参考范围**解析不出来**（12 病例 26060 行检验文本，范围格式命中 0）。所以不能问"有没有超标"，只能问"有没有大于 10"——**阈值由我们给，答案靠数** |
| **不许要临床判断** | 没有医生。任何"这个值对这位病人算不算异常""这个诊断对不对"的题**不出** |
| **答案必须能从文档里数出来或找出来** | 只有这样机器才能独立重算，人工只做抽查 |

## 二、题目来源：只用侦察确认过的字段

| 来源 | 规模（12 病例） | 网格？ | 用来出什么题 |
| --- | --- | --- | --- |
| **order_execution** | 24 份 / 25,366 行 / **8,179 个日期格** | ✅ 9 列 | 算一下的主力：计数、时间跨度、时段分布 |
| **laboratory_report** | 14 份 / 26,060 行 / 18% 数字 | ✅ 9 列 | 算一下：值计数、阈值计数、采集次数 |

**已被排除的题**（写下来免得以后有人再提）：
- 任何"超出参考范围"的题 → 参考范围解析不了
- 输血相关 → `transfusion_record` 12 个病例里只有 1 份，太稀有
- 病理/影像结论类 → 叙述文档，答案要临床判断

## 二之二、一个必须先解决的问题：`order_execution` 的"一条医嘱"定义不稳

实测（12 病例）：用两种定义数"一条医嘱"，结果差 **13%~69%**：

| 定义 | 含义 |
| --- | --- |
| 行带数 | 按纵坐标聚类出来的行 |
| 日期格数 | 带时间戳的格子数 |

| 病例 | 行带数 | 日期格数 | 比值 |
| --- | --- | --- | --- |
| CASE-03 | 363 | 321 | 1.13 |
| CASE-05 | 1208 | 834 | 1.45 |
| CASE-04 | 1200 | 709 | **1.69** |
| CASE-100 | 3273 | 2069 | 1.58 |

比值从 1.13 到 1.69 都有 → **"一条医嘱"现在没有可靠定义**（可能是长医嘱折行、也可能一条医嘱有多个时间戳）。

**处置原则（写进方法论）**：
> **凡是答案依赖"行"这个概念的问题，先确认那张表的行定义稳不稳；不稳就改成"格"级问题。**

- `laboratory_report` 的行定义**已验证**（几何 139 vs 模型 141；CASE-06 330 vs 315）→ 可以出"行"级问题
- `order_execution` 的行定义**未验证** → **只出"格"级问题**：不问"医嘱几条"，改问"涉及多少个不同日期""凌晨时段有多少个时间格"

## 三、算一下型（每病例 3 题，共 36 题）

判卷规则统一为：**数值必须完全相等**（归一化后）；同时必须给出出处。
下面"答案怎么算"那一列，就是机器独立重算用的方法——**和被测系统走的是不同代码路径**。

| ID | 来源 | 问题 | 答案怎么算（判卷基准） |
| --- | --- | --- | --- |
| ~~C1~~ | order_execution | ~~用药医嘱一共开了多少条？~~ | **暂缓**：行定义不稳（比值 1.13~1.69） |
| C2 | order_execution | 这些医嘱一共涉及多少个**不同的日期**？ | 抽所有日期格 → 归一化成 YYYY-MM-DD → 去重计数（**格级，不依赖行**） |
| C3 | order_execution | 医嘱里有多少个带时间戳的记录标记了静脉给药？ | 数同时含"静脉"和时间的行 |
| C4 | order_execution | 最早和最晚的**日期**相隔多少天？ | max(日期) − min(日期)（格级） |
| C5 | order_execution | 哪一天的医嘱**记录数**最多？那天有几条？ | 按日期分组数日期格 → 取最大（格级） |
| C6 | order_execution | 有几天的时间戳个数在 10 个以上？ | 按日期分组数日期格 → 数 ≥10 的天数 |
| C7 | order_execution | 凌晨 00:00 到 06:00 之间的**时间格**有多少个？ | 抽时刻格 → 落在区间内计数 |
| C8 | order_execution | 相邻两个时间戳之间，间隔最长的小时数？ | 时刻排序 → 相邻差最大（小时） |
| C9 | laboratory_report | 这个病例的检验一共抽了**多少行**？ | 值列几何聚类出的行数（**该表行定义已验证**） |
| C10 | laboratory_report | 检验里出现了多少个不同的检验项目？ | 项目名列去重计数 |
| C11 | laboratory_report | 白细胞这个项目一共测了几次？ | 项目名匹配 → 计数 |
| C12 | laboratory_report | 白细胞的测量值里，有多少次大于 10？ | 数值比较 → 计数（阈值由题面给出） |
| C13 | laboratory_report | 检验一共跨了几个不同的采集日期？ | 页脚采集时间 → 归一化到日期 → 去重计数 |
| C14 | laboratory_report | 相邻两次检验相隔最长的小时数？ | 采集时刻排序 → 相邻差最大 |
| C15 | laboratory_report | 带小数点的检验值有多少个？ | 值文本含小数点 → 计数 |
| C16 | laboratory_report | 检验值里最大的数是多少？ | 数值型值取最大 |
| C17 | 全病例 | 这个病例一共有几份文档？ | 数目录 |
| C18 | 全病例 | 这个病例涉及多少种文档类型？ | 按 category 去重计数 |

> 每病例从上面挑 3 个模板，保证 12 个病例合计 36 题，且**算一下型尽量落在 `laboratory_report`**
> （那张表的行定义已经验证过）；`order_execution` 只出格级问题。

## 四、查一下型（每病例 1 题，共 12 题）

| ID | 来源 | 问题 | 判卷基准 |
| --- | --- | --- | --- |
| L1 | laboratory_report | 最后一次检验的采集时间是什么？ | 页脚采集时间，取最晚 |
| L2 | laboratory_report | 第一次检验的采集日期是哪天？ | 页脚采集时间，取最早 |
| L3 | laboratory_report | 某个指定项目的最大值是多少？ | 该项目数值最大 |
| L4 | order_execution | 最早一条医嘱的日期是哪天？ | 日期最小值 |
| L5 | order_execution | 最晚一条医嘱的日期是哪天？ | 日期最大值 |
| L6 | medical_record_front_page | 入院日期是哪天？ | 首页日期字段 |
| L7 | medical_record_front_page | 出院日期是哪天？ | 首页日期字段 |
| L8 | ecg_report | 一共做了几次心电图检查？ | 文档数 |

> 查一下型的答案**必须逐字出现在它引用的行里**——所以判卷是"字符串／数值匹配 + 引用解析"，
> 机器全自动，人工只抽查。

## 五、库里真没有型（每病例 1 题，共 12 题）

**这一型是整份题库里最值钱的**，因为它测的是"该说没有时说了没有"。

| ID | 问题 | 素材够不够（12 病例实测） |
| --- | --- | --- |
| A1 | 这个病例有没有**输血**记录？ | ✅ **11/12 个病例可**（`transfusion_record` 文档数为 0） |
| A2 | 这个病例有没有做过**手术**？ | ✅ **3/12 个病例可**（CASE-06 / CASE-09 / CASE-10） |
| A3 | 这个病例有没有**影像检查报告**？ | ✅ **7/12 个病例可** |
| A4 | 这个病例有没有测过**某个指定项目**？ | ✅ 按项目名穷搜，命中 0 才用 |
| A5 | ~~有没有药物过敏记录？~~ | ❌ **不可用**：实测每个病例都有 5~23 处"过敏"命中 |

> **每个病例只出 1 题**，优先顺序 A1 → A3 → A2 → A4。12 个病例都凑得出来。
> 判卷：正确答案 = 「没有记录」；**答出一个不存在的记录 = 最严重错误**（错误的肯定结论）。

## 六、谁来核答案：你核，不用医生

| 题型 | 机器能做什么 | 你要做什么 |
| --- | --- | --- |
| C 算一下 | **独立重算**（脚本走另一套代码路径） | 抽 **6 题**（每型 2 题）看一眼 |
| L 查一下 | 匹配答案 + 验证引用可解析 | 抽 **4 题**看一眼 |
| A 真没有 | **穷搜全病例**，报告命中数 | **12 题全看**——"没搜到"不等于"没有"，这一型必须人确认 |

**你实际要核的是 22 题左右，不是 60 题。**

**工作方式**：我产出一张核对表，每道题给你：**问题 / 我的答案 / 出处（哪份文档第几行）/ 机器重算结果**。
你只需要确认"出处里写的就是这个答案"——**不需要翻整份病历**。

---

## 七、答案怎么生产（防循环）

1. **机器推导**：用几何层（值列聚类）与规则解析，**不调用任何模型**
2. **出处必带**：每个答案附 `文档:L行号`
3. **不同代码路径**：算一下型的重算脚本和建库脚本不是同一份代码
4. **你抽查**：按上表核 22 题，报"你核过的题里与机器一致的比例"

**注意**：如果某个病例的几何层解析失败（大病例），**这道题就标记"不可判"，不计入分母**——
而不是让它变成 0 分。
