# AI-Ready 相关工作对照表（v0.1，会后工作包 A）

> **本表的用途**：回答师兄会上那句"AI ready 跟不 AI ready 的东西，它的本质的一个点是什么"——先看清别人怎么定义、怎么设对照、怎么证明收益，再决定我们怎么做。
>
> **完成判据（会议原文）**：用户能**用自己的话**解释精选论文如何证明 AI-ready，而不是只重复关键词；有价值的论文与对照表发师兄共同分析。
> **诚实说明**：本版由检索结果与已有阅读种子化，**多数条目尚未通读全文**。`核对状态` 列标出"已通读 / 摘要级 / 待核对"——只有"已通读"的条目才允许引用到论文里。**只看摘要不算完成。**

## 二、这张表告诉我们的三件事（**有检索边界的待核缺口，不是结论**）

1. **"AI-ready"这个词已经被占了三层**：通用数据治理框架（#4/#5/#6 的分级与维度）、临床人工量表（#3 的 0–2 级）、序列化/表示实验（#1/#2）。**我们不能自称提出这个词，也不能只做其中任何一层。**
2. **在我们检索到的范围内**（关键词 + 近一年 + 若干相邻概念），现有工作的对象多为"已是结构化或合成的输入"（#1/#2/#14）或"抽取/合成质量"（#7/#8）或"人工量表"（#3）。**"从真实医院扫描件起、把每个准备动作的边际效应分开量"这一组合，本轮检索未命中同形工作**——但这是**检索覆盖内的待核缺口，不是"证明无人研究"**。下一轮必须补：相邻概念（data readiness / clinical NLP preprocessing / information extraction 评估）、前后向引文追踪、以及不止近一年的时间窗。
3. **三个必须避开的坑**：
   - **HoloBench 已占"聚合随规模退化、max/min 抗退化"**（#10）——我们的队列级观察要写成复现与延伸，不能写成发现。
   - **#2 已经给出"表示选择对 QA 与 ML 影响相反"的强证据**：我们不能笼统写"结构化更好用"，必须**分任务类型**说，并且要解释与它的差别（它比的是"结构化→叙述"，我们比的是"扫描件→可用数据"）。
   - **#2 还给出了"检索归因"与"预算敏感性"两件现成工具**（无检索基线、token 预算扫描）——我们若不采用，需要说明理由。
   - **去标识化/合规也是准备动作**（#12）——我们目前六层里没有这一层，要么补上，要么明确说明不在主张范围内。
